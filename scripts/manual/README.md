# Руководство Word: сборка

`docs/MailArchiver_Руководство.docx` собирается из `docs/ru/*.md` и записи `CHANGELOG.md` о текущей версии
одной командой из корня репозитория:

```bash
bash scripts/manual/build.sh
```

Руководство не собирается с нуля, а **правится на месте**: берётся руководство прежнего выпуска, и в нём
меняется только то, что изменилось в Markdown. Оформление, рисунки и всё неизменное остаются побайтно
прежними — это проверяется после каждой сборки.

## Что нужно

- Python 3 с модулями `pypdf` и `Pillow` (`pip install pypdf Pillow`);
- LibreOffice (`soffice`) — для PDF, по которому считаются номера страниц оглавления;
- poppler-utils (`pdftotext`, `pdfinfo`), `zip`, `unzip`, `git`.

На macOS: `brew install --cask libreoffice`, `brew install poppler`. Номера страниц зависят от шрифтов:
документ набран Calibri, а в Linux LibreOffice подставляет метрически совместимый Carlito. Без Carlito
(`fonts-crosextra-carlito`) страницы могут разойтись на строку-другую — оглавление будет верным для этой
машины, но проверка «Что нового на одной странице» может повести себя иначе. Привычнее всего собирать в Linux.

## Откуда берётся прежнее руководство

По умолчанию — из последнего коммита, где менялся `docs/MailArchiver_Руководство.docx`: оттуда же берутся
`docs/ru` и `CHANGELOG.md`, из которых оно было собрано. Другая точка отсчёта:

```bash
bash scripts/manual/build.sh --base v1.14.0                    # метка или коммит
bash scripts/manual/build.sh --base-docx old.docx --base-root DIR   # без git: DIR — с docs/ru и CHANGELOG.md
bash scripts/manual/build.sh --no-install                      # результат только в build/manual/out.docx
```

Рабочие файлы — в `build/manual/` (в git не попадают): `update.log` (что поменялось и почему),
`manifest.json`, `pdf/out.pdf` — посмотреть результат.

## Что делает сборка

`update.py` — сам находит, что поменять:

| Шаг | Что |
|---|---|
| 0 | номера глав сдвинулись в `chapters.py` (вставлена глава) — перенумерация заголовков и ссылок «глава 17», «раздел 17.3» |
| A | версия и дата на обложке, в колонтитуле, свойствах документа и подписи в конце |
| B | «Что нового» — заново из записи `CHANGELOG.md`; «глава «Почтовые серверы»» получает номер главы, обороты из `REFS` — «(гл. N)» |
| C | изменившиеся главы — трёхсторонним слиянием (`merge3.py`): прежний Markdown ↔ документ ↔ новый Markdown; новые снимки — по образцу прежних |
| F | снимок экрана изменился, а Markdown нет — заменяется сам рисунок (по совпадению пикселей с прежним) |
| E | новые главы — целиком, на своё место, со снимками |
| P | изменился `05-parameters-reference.md` — таблицы приложения «Справочник параметров» |
| D | определения новых нумерованных списков |

Потом: PDF → оглавление по закладкам PDF → повтор, пока номера страниц не перестанут меняться → проверки:

- `verify.py` — версия и дата; состав глав; заголовки, рисунки и **каждая строка** изменившихся разделов, новых
  глав и записи CHANGELOG — в своей главе; нумерованные списки; неизменное — побайтно прежнее; части пакета;
- `layout_check.py` — заголовок или «…:» последней строкой страницы, текст за полем, подпись не с рисунком;
- `whatsnew_pages.py` — «Что нового» помещается на одну страницу.

Любая ошибка — ненулевой код, и `docs/` не трогается. Если всё прошло — руководство записывается в `docs/`.

## Если сборка остановилась

| Сообщение | Что делать |
|---|---|
| «docs/ru/X.md … в chapters.py его нет» | новая глава: впишите её в `CHAPTERS` в `chapters.py` с номером (номера следующих — сдвиньте); разделы «## 22.1.» — номер файла в `MD_NUM` |
| «в документе глава «…», которой нет в chapters.py» | главу переименовали или удалили — так сборка не умеет; правьте `chapters.py` и документ вручную |
| «документ расходился с прежним Markdown в изменившемся месте» | в `.docx` правили руками то же место, что и в Markdown; подробности — в `update.log` |
| «Что нового»: стр. N, глава 1: стр. N+2 | запись `CHANGELOG.md` длиннее страницы — сократите |
| ширины колонок, слова в заголовке таблицы рвутся | ширины — в `TABLE_WIDTHS` в `chapters.py` |
| ссылка на главу словами в «Что нового» без номера | оборот — в `REFS` в `chapters.py` |

Отладка: `python3 scripts/manual/outline.py build/manual/unpacked/word/document.xml` — заголовки с номерами
элементов; `python3 scripts/manual/show.py …/document.xml 120 121` — XML этих элементов.

## Файлы

| Файл | Что |
|---|---|
| `build.sh` | вся сборка |
| `chapters.py` | состав руководства — **единственное, что правится руками** |
| `update.py` | правки документа |
| `verify.py` | проверка результата |
| `mdrender.py` | Markdown → XML Word в оформлении руководства |
| `merge3.py`, `docunits.py`, `bodyindex.py` | трёхстороннее слияние и разбор документа |
| `renumber.py` | перенумерация глав |
| `appendix.py` | таблицы приложения |
| `toc.py`, `toc_apply.py` | оглавление по PDF |
| `layout_check.py`, `check_pages.py`, `whatsnew_pages.py` | проверки вёрстки |
| `outline.py`, `show.py` | отладка |

Сборка проверена так: руководства 1.13.0 (от 1.12.0) и 1.14.0 (от 1.13.0) собраны заново этими скриптами —
`document.xml` побайтно тот же, что в выпусках.
