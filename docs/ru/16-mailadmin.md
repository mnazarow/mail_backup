# 16. Вход в ящики через администратора почты

Чтобы копировать ящик по IMAP, службе нужно в него войти. Обычно — паролем самого ящика, и на
сотнях ящиков это превращается в отдельную работу: собрать пароли, обновлять их после каждой смены,
разбираться, почему у десятка сотрудников «неверный пароль».

Многие почтовые серверы умеют пускать **учётную запись администратора «от имени» ящика**: служба
предъявляет пароль администратора и указывает, в чей ящик войти. Тогда пароли сотрудников не
нужны вовсе, а смена пароля сотрудником копирование не ломает.

Настройка — «Настройки → 🗝️ Вход в ящики через администратора почты».

## Какие серверы это умеют

| Сервер | Как называется | Способ в MailArchiver |
|--------|----------------|-----------------------|
| **Dovecot** | master users | «SASL PLAIN с authzid» или «Логин с разделителем» |
| **Cyrus IMAP** | proxy authorization (администраторы из `admins`/`proxyservers`) | «SASL PLAIN с authzid» |
| **Zimbra** | вход администратора через SASL PLAIN с authzid | «SASL PLAIN с authzid» |
| **Axigen** | такой вход по IMAP в документации **не описан** | скорее всего не сработает — проверьте кнопкой; если нет, оставьте вход по паролям |
| **Microsoft Exchange / 365** | FullAccess + вход «ящик\администратор» или OAuth | не поддерживается этим механизмом |

«SASL PLAIN с authzid» — стандартный способ (RFC 4616): в одной команде входа передаются логин
администратора, его пароль и адрес ящика, который нужно открыть. «Логин с разделителем» — вход
вида `ivanov@company.ru*archmaster` с паролем администратора (так умеет Dovecot при настройке
`auth_master_user_separator`).

## Настройка

1. На почтовом сервере заведите учётную запись администратора для архива (пример для Dovecot —
   ниже). Лучше отдельную, только для MailArchiver: её входы будет легко найти в журналах сервера.
2. В MailArchiver заполните «Сервер администратора» (ровно как у ящиков, например
   `mx.company.ru`), логин и пароль, способ входа; включите «Входить в ящики через
   администратора» и **сохраните**.
3. Нажмите **«Проверить вход администратора»**. Можно указать адрес ящика для проверки; если поле
   пустое, берётся первый ящик этого сервера. Проверка только входит и выходит — письма не
   читаются.
4. Если вход работает — **«Перевести ящики сервера на вход через администратора»**: у всех ящиков
   этого сервера со способом «Логин и пароль» способ входа сменится на «Через администратора
   почты». Сохранённые пароли ящиков **не удаляются** — кнопка «Вернуть вход по паролям» в любой
   момент возвращает всё как было.

Способ входа можно менять и у отдельного ящика — в его карточке, поле «Способ входа», вариант
«Через администратора почты (без пароля ящика)». Для новых
сотрудников, которые заводятся из кадровой выгрузки, включите «Сотрудники → Входить в новые ящики
через администратора» (действует, если сервер в шаблоне ящиков совпадает с сервером
администратора).

## Безопасность

- Пароль администратора отправляется **только на «Сервер администратора»**. Ящик с другим
  адресом сервера (опечатка или чужой сервер) его не получит — вход такого ящика завершится
  ошибкой «Вход администратора разрешён только для сервера …».
- Пароль хранится в базе в зашифрованном виде (ключом `secret.key`) и в интерфейс не отдаётся.
- Кто владеет этим паролем, может читать любой ящик сервера. Выдайте учётной записи минимальные
  права, какие позволяет сервер, и не используйте её ни для чего, кроме архива.
- Проверки входа записываются в аудит (`mailadmin_check`).

## Пример: Dovecot 2.3

```
# /etc/dovecot/conf.d/10-auth.conf
auth_master_user_separator = *          # нужно только для способа «Логин с разделителем»

passdb {
  driver = passwd-file
  args = /etc/dovecot/master-users
  master = yes
  result_success = continue             # после проверки администратора убедиться, что ящик существует
}
```

```bash
# создать учётную запись archmaster с паролем (хеш SHA512-CRYPT)
echo "archmaster:$(doveadm pw -s SHA512-CRYPT)" | sudo tee -a /etc/dovecot/master-users
sudo chown root:dovecot /etc/dovecot/master-users && sudo chmod 640 /etc/dovecot/master-users
sudo systemctl reload dovecot
```

В Dovecot 2.4 блоки `passdb` записываются иначе (у каждого своё имя) — смотрите раздел
«Master users» документации своей версии. Вход администратора в Dovecot проверен вживую в обоих
режимах: копирование ящиков идёт так же, как при входе по паролю.

## Если сервер отказал

Ошибка «Вход через учётную запись администратора почты отклонён сервером» после кнопки проверки
означает одно из:

- неверный логин или пароль администратора;
- сервер не поддерживает такой вход (например Axigen) — оставьте вход по паролям ящиков;
- выбран не тот способ: попробуйте второй («SASL PLAIN с authzid» ↔ «Логин с разделителем»);
- у учётной записи нет права входить в чужие ящики (в Cyrus — не указана в `admins` /
  `proxyservers`).

Ящики при этом не меняются: переводить их имеет смысл только после удачной проверки.
