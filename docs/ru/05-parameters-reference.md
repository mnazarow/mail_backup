# Справочник параметров MailArchiver

Полное описание каждого параметра: назначение, рекомендация по настройке, пример значения и значение по умолчанию. Параметры сгруппированы так же, как на странице «Настройки» в веб-интерфейсе.

## 🌐 Сервер и сеть

### Адрес прослушивания  
`server.host`

IP-адрес, на котором веб-интерфейс принимает подключения. 127.0.0.1 — только с самого сервера (безопасно, обычно за reverse proxy). 0.0.0.0 — со всех сетевых интерфейсов.

- **Рекомендация:** Оставьте 127.0.0.1 и поставьте перед сервисом nginx/traefik с HTTPS. Ставьте 0.0.0.0 только если понимаете риски и включили аутентификацию.
- **Пример:** `127.0.0.1`
- **По умолчанию:** `127.0.0.1`

### Порт веб-интерфейса  
`server.port`

TCP-порт, на котором работает веб-интерфейс.

- **Рекомендация:** Порт по умолчанию 8493 подходит в большинстве случаев. Меняйте, если он занят.
- **Пример:** `8493`
- **По умолчанию:** `8493`

### Внешний URL  
`server.public_url`

Полный адрес, по которому интерфейс открывают в браузере. По нему проверяется источник запросов (защита от подделки запросов с чужих сайтов), в том числе у WebSocket — за обратным прокси, который меняет заголовок Host, без него интерфейс работать не будет.

- **Рекомендация:** Заполните, если работаете за reverse proxy с доменом и HTTPS.
- **Пример:** `https://mail-backup.example.ru`
- **По умолчанию:** `(пусто)`

### За обратным прокси  
`server.behind_proxy`

Доверять заголовкам X-Forwarded-* (реальный адрес клиента, протокол). Включайте, только если перед сервисом стоит доверенный nginx/traefik, и обязательно заполните «Адреса доверенных прокси».

- **Рекомендация:** true при работе за reverse proxy, иначе false.
- **Пример:** `false`
- **По умолчанию:** `false`

### Адреса доверенных прокси  
`server.trusted_proxies`

Кому можно верить в заголовке X-Forwarded-For. Настоящим адресом клиента считается первый справа хоп, которого нет в этом списке: левую часть цепочки дописывает сам клиент, и без списка защиту от подбора пароля обходит любой, кто подставит заголовок. Допустимы отдельные адреса и сети (10.0.0.0/8), через запятую.

- **Рекомендация:** Адрес вашего nginx/traefik. «*» отключает проверку — так делать не нужно.
- **Пример:** `127.0.0.1, 10.0.0.0/8`
- **По умолчанию:** `127.0.0.1, ::1`

## 🔒 Безопасность

### Требовать вход  
`security.auth_enabled`

Включает обязательную аутентификацию в веб-интерфейсе. При первом запуске создаётся администратор.

- **Рекомендация:** Всегда держите включённой, кроме изолированного стенда без доступа извне.
- **Пример:** `true`
- **По умолчанию:** `true`

### Срок жизни сессии, часов  
`security.session_ttl_hours`

Через сколько часов после входа сессия истечёт и потребуется войти заново.

- **Рекомендация:** 8–12 часов для рабочего дня. Меньше — безопаснее, но чаще вход.
- **Пример:** `12`
- **По умолчанию:** `12`

### Тайм-аут бездействия, минут  
`security.session_idle_minutes`

Автоматический выход при отсутствии активности указанное число минут.

- **Рекомендация:** 30–60 минут. Для строгих требований — 15.
- **Пример:** `60`
- **По умолчанию:** `60`

### Минимальная длина пароля  
`security.min_password_length`

Минимальное число символов в пароле пользователя веб-интерфейса.

- **Рекомендация:** Не меньше 8; лучше 12+ и парольная фраза.
- **Пример:** `8`
- **По умолчанию:** `8`

### Порог блокировки входа  
`security.max_login_attempts`

Сколько неудачных попыток входа допускается для одной учётной записи с одного адреса; затем этот адрес для неё временно блокируется (чужие попытки не закрывают вход настоящему владельцу). От этого числа считаются и остальные пределы: адрес по всем учётным записям — ×10; неверные коды 2FA по учётной записи — ×2 за период блокировки и ×10 за сутки (резервные коды при этом работают); проверки пароля одного почтового ящика — ×2, всех ящиков вместе — ×12.

- **Рекомендация:** 5 — разумный баланс. Слишком мало мешает при опечатках.
- **Пример:** `5`
- **По умолчанию:** `5`

### Длительность блокировки, минут  
`security.lockout_minutes`

На сколько минут блокируется вход после превышения порога попыток (и за какой период они считаются).

- **Рекомендация:** 15 минут.
- **Пример:** `15`
- **По умолчанию:** `15`

### Cookie только по HTTPS  
`security.secure_cookie`

Помечает cookie сессии флагом Secure — браузер отправит её только по HTTPS.

- **Рекомендация:** Включите, когда сервис доступен по HTTPS. По HTTP держите выключенным, иначе вход не сработает.
- **Пример:** `false`
- **По умолчанию:** `false`

### Обязательный двухфакторный вход  
`security.require_2fa`

Каждый администратор обязан включить вход с кодом из приложения-аутентификатора (Яндекс Ключ, Google Authenticator и т. п.). Пока 2FA не включена, после входа открывается только её настройка. Вход сотрудников по своему ящику это не затрагивает.

- **Рекомендация:** true, если интерфейс доступен из интернета или из общей сети офиса.
- **Пример:** `true`
- **По умолчанию:** `false`

### Вход сотрудников по паролю ящика  
`security.mailbox_login`

Сотрудник входит в веб-интерфейс своим email и паролем почтового ящика и видит только свой архив. Пароль проверяется входом на почтовый сервер. Число таких проверок ограничено (на ящик и в целом), чтобы страницу входа нельзя было использовать для подбора паролей почты, а защита почтового сервера не заблокировала адрес MailArchiver.

- **Рекомендация:** Выключите, если сотрудникам не нужен доступ к своему архиву или почтовый сервер строго блокирует адреса после неудачных входов (fail2ban).
- **Пример:** `true`
- **По умолчанию:** `true`

### Проверять TLS-сертификат IMAP  
`security.imap_ssl_verify`

Проверять подлинность сертификата почтового сервера при подключении по SSL/STARTTLS.

- **Рекомендация:** Держите включённым. Отключайте только для внутренних серверов с самоподписанным сертификатом — это снижает защиту от подмены.
- **Пример:** `true`
- **По умолчанию:** `true`

## 💾 Хранилище

### Сжимать письма (gzip)  
`storage.compress`

Сжимать каждое письмо при сохранении. Экономит место (текстовые письма сжимаются в 2–4 раза), но чуть увеличивает нагрузку на процессор.

- **Рекомендация:** Включайте при нехватке места. Для максимальной скорости и совместимости с внешними инструментами — выключено.
- **Пример:** `false`
- **По умолчанию:** `false`

### Принудительный сброс на диск  
`storage.fsync`

После записи письма принудительно сбрасывать данные на диск (fsync). Надёжнее при сбоях питания, но медленнее.

- **Рекомендация:** Включено для надёжности. Выключайте только на быстрых SSD, где важна максимальная скорость.
- **Пример:** `true`
- **По умолчанию:** `true`

### Минимум свободного места, МБ  
`storage.min_free_space_mb`

Если свободного места меньше этого значения, бэкап не начнётся (защита от заполнения диска).

- **Рекомендация:** 500–2000 МБ. Для больших ящиков увеличьте.
- **Пример:** `500`
- **По умолчанию:** `500`

### Проверять после записи  
`storage.verify_after_write`

После сохранения письма сверять его размер и контрольную сумму (SHA-256). Гарантирует, что копия записалась без повреждений.

- **Рекомендация:** Держите включённым — стоит недорого, а защищает от «тихой» порчи данных.
- **Пример:** `true`
- **По умолчанию:** `true`

### Шифровать письма  
`storage.encrypt`

Новые письма сохраняются зашифрованными (AES-256-GCM). Уже сохранённые остаются как были — зашифровать их можно кнопкой ниже. Без файла ключа зашифрованные письма НЕ ПРОЧИТАТЬ ничем: храните копию ключа отдельно от каталога данных. Выгрузки (EML/MBOX/PST) не шифруются.

- **Рекомендация:** Включайте, если копии каталога писем уходят на внешние диски или в облако, а ключ хранится отдельно. От кражи всего сервера целиком не защищает — для этого шифрование диска (LUKS).
- **Пример:** `true`
- **По умолчанию:** `false`

### Файл ключа шифрования  
`storage.encryption_key_file`

Путь к файлу ключа (64 шестнадцатеричных символа). Пусто — storage.key в каталоге данных (создаётся автоматически при первом включении). Надёжнее вынести ключ из каталога данных: создайте его командой «mailarchiver storage-key --generate ПУТЬ».

- **Рекомендация:** Путь вне каталога данных, например /etc/mailarchiver/storage.key (права 0640, группа службы).
- **Пример:** `/etc/mailarchiver/storage.key`
- **По умолчанию:** `(пусто)`

## 📥 Резервное копирование

### Одновременных заданий  
`backup.max_concurrent_jobs`

Сколько заданий (бэкап/экспорт/восстановление) выполняется параллельно, от 1 до 16. С одним ящиком одновременно работает не больше одного задания.

- **Рекомендация:** 2–4 для сервера с несколькими ядрами. Больше — быстрее при многих ящиках, но выше нагрузка на сеть и диск.
- **Пример:** `2`
- **По умолчанию:** `2`

### Размер пакета загрузки  
`backup.fetch_batch_size`

Сколько писем запрашивать у сервера за одну команду. Больше — быстрее, но выше пиковое потребление памяти.

- **Рекомендация:** 100–300. Для медленных серверов уменьшите, для быстрых можно увеличить.
- **Пример:** `200`
- **По умолчанию:** `200`

### Тайм-аут подключения, сек  
`backup.connect_timeout_s`

Сколько секунд ждать установления соединения с почтовым сервером.

- **Рекомендация:** 30. Увеличьте для медленных/удалённых серверов.
- **Пример:** `30`
- **По умолчанию:** `30`

### Тайм-аут операций, сек  
`backup.socket_timeout_s`

Максимальное время ожидания ответа на команду IMAP.

- **Рекомендация:** 120. Для очень больших писем/вложений увеличьте до 300.
- **Пример:** `120`
- **По умолчанию:** `120`

### Число повторов  
`backup.retry_attempts`

Сколько всего попыток даётся заданию при временных сбоях (обрыв связи, тайм-аут): 4 — первый запуск и до трёх повторов с нарастающей паузой.

- **Рекомендация:** 3–5. Помогает пережить кратковременные проблемы сети.
- **Пример:** `4`
- **По умолчанию:** `4`

### Начальная задержка повтора, сек  
`backup.retry_initial_delay_s`

Пауза перед первым повтором. Далее растёт по экспоненте.

- **Рекомендация:** 2–5 секунд.
- **Пример:** `2`
- **По умолчанию:** `2`

### Множитель задержки  
`backup.retry_backoff`

Во сколько раз увеличивается пауза с каждой попыткой (2 = удвоение).

- **Рекомендация:** 2.0.
- **Пример:** `2.0`
- **По умолчанию:** `2.0`

### Сохранять флаги писем  
`backup.download_flags`

Сохранять пометки писем (прочитано, важное, отвечено и т.п.). Нужно, чтобы при восстановлении статусы вернулись как были.

- **Рекомендация:** Включено.
- **Пример:** `true`
- **По умолчанию:** `true`

### Пропускать письма крупнее, МБ  
`backup.skip_larger_than_mb`

Не сохранять письма больше указанного размера (0 — сохранять все). Полезно, если не нужны гигантские вложения.

- **Рекомендация:** 0 (сохранять всё). Ставьте, например, 50, если хотите исключить огромные вложения.
- **Пример:** `0`
- **По умолчанию:** `0`

### Терпеть нечитаемую папку, прогонов  
`backup.unreadable_folder_grace_runs`

Сколько прогонов подряд папка, которую почтовый сервер отказывается открыть, считается ОШИБКОЙ и делает копию неполной. После этого числа она переходит в разряд «известных нечитаемых»: сервис продолжает пробовать её каждый раз, сообщает о ней в итоге задания, но задание больше не помечается неудачным. Как только сервер отдаст папку, счётчик сбрасывается и письма копируются. 0 — считать ошибкой всегда.

- **Рекомендация:** 3. Бесконечное «КОПИЯ НЕПОЛНАЯ» из-за папки, которую на сервере уже не починить, приучает не читать предупреждения — и настоящая пропажа писем остаётся незамеченной.
- **Пример:** `3`
- **По умолчанию:** `3`

### Только эти папки  
`backup.folder_include`

Белый список: копировать ТОЛЬКО перечисленные папки (и вложенные). Пусто — копировать все папки.

- **Рекомендация:** Оставьте пустым, чтобы копировать весь ящик. Заполняйте, если нужны только отдельные папки.
- **Пример:** `["INBOX", "Отправленные"]`
- **По умолчанию:** `[] (все)`

### Исключить папки  
`backup.folder_exclude`

Чёрный список: НЕ копировать перечисленные папки (и вложенные). Применяется после белого списка.

- **Рекомендация:** Часто исключают спам и корзину: ["Спам", "Корзина"] или для Gmail ["[Gmail]/Spam", "[Gmail]/Trash"].
- **Пример:** `["Спам", "Корзина"]`
- **По умолчанию:** `[] (не исключать)`

## 🧹 Хранение и очистка

### Общая очистка по сроку  
`retention.enabled`

Ежедневно удалять из локальной копии письма старше «Хранить дней» — у ящиков, для которых выбран срок «как в общих настройках». Свой срок ящика (карточка ящика → «Хранение копий») действует всегда, независимо от этого переключателя. Письма на почтовом сервере не трогаются.

- **Рекомендация:** Выключено, если архив хранится бессрочно. Включайте при ограниченном месте на диске.
- **Пример:** `false`
- **По умолчанию:** `false`

### Хранить дней  
`retention.keep_days`

Общий срок хранения локальной копии (0 — бессрочно). Работает, только когда включена «Общая очистка по сроку». Если срок увеличить, письма, удалённые по старому сроку и ещё лежащие на сервере, снова скачаются при следующем копировании.

- **Рекомендация:** 0 для полного архива. Например, 365 — хранить копии за последний год.
- **Пример:** `0`
- **По умолчанию:** `0`

### Время ежедневной очистки  
`retention.cron`

Когда запускать очистку по срокам хранения (cron: минуты часы день месяц день_недели, в часовом поясе планировщика). Очистка ставится только тем ящикам, у которых есть что удалять.

- **Рекомендация:** Ночью, после резервного копирования: 30 4 * * *.
- **Пример:** `30 4 * * *`
- **По умолчанию:** `30 4 * * *`

### Хранить записей истории  
`retention.keep_last_runs`

Сколько последних записей истории бэкапов держать в журнале на каждый ящик.

- **Рекомендация:** 30–100.
- **Пример:** `30`
- **По умолчанию:** `30`

## 🛰️ Копия вне сервера и снимки базы

### Копировать архив вне сервера  
`replica.enabled`

Каждый день отправлять копию архива (файлы писем и снимки базы) в сетевую папку, на другой сервер по SSH или в S3-хранилище. Защищает от потери сервера целиком: сгоревший диск, шифровальщик, удалённая виртуальная машина. Первая копия идёт долго (весь архив), дальше — только новые письма.

- **Рекомендация:** Включите: архив на одном сервере — это одна копия. Место копии — на другом железе и желательно в другом здании.
- **Пример:** `true`
- **По умолчанию:** `false`

### Куда копировать  
`replica.target`

«Сетевая папка или диск» — любой каталог, смонтированный на сервере (SMB, NFS, USB-диск). «Сервер по SSH» — другой Linux-сервер, копирование rsync-ом. «S3» — облачное или своё S3-хранилище (Yandex Object Storage, VK Cloud, MinIO).

- **Рекомендация:** S3 в другом дата-центре — надёжнее всего; сетевая папка — проще всего.
- **Пример:** `s3`
- **По умолчанию:** `dir`

### Время копирования  
`replica.cron`

Когда отправлять копию (cron: минуты часы день месяц день_недели, в часовом поясе планировщика). В это же время снимается снимок базы, даже если копия вне сервера выключена.

- **Рекомендация:** После ночного копирования ящиков и очистки: 0 6 * * *.
- **Пример:** `0 6 * * *`
- **По умолчанию:** `0 6 * * *`

### Класть в копию снимки базы  
`replica.include_db`

Без базы копия писем — это просто файлы: ни поиска, ни просмотра, ни выгрузки по ящикам. Снимок базы содержит индекс писем, ящики (пароли — зашифрованы), расписания и настройки. При включённом шифровании писем снимок тоже шифруется.

- **Рекомендация:** Оставьте включённым.
- **Пример:** `true`
- **По умолчанию:** `true`

### Хранить снимков базы  
`replica.db_snapshot_keep`

Сколько последних ежедневных снимков базы хранить на сервере (каталог snapshots в каталоге данных); копия вне сервера хранит столько же. Снимок делается «на ходу», проверяется на целостность и сжимается. 0 — не делать снимков (тогда и копия уйдёт без базы).

- **Рекомендация:** 3–7. Снимок занимает примерно треть размера базы.
- **Пример:** `3`
- **По умолчанию:** `3`

### Удалять в копии удалённое из архива  
`replica.mirror_deletions`

Если письмо удалено из архива (очистка по сроку хранения), удалить его и в копии. Выключите, если копия должна хранить всё, что когда-либо попадало в архив.

- **Рекомендация:** Включено, если в архиве настроены сроки хранения — иначе копия будет расти бесконечно.
- **Пример:** `true`
- **По умолчанию:** `true`

### Защита от массового удаления, %  
`replica.max_delete_percent`

Если прогон собирается удалить в копии больше этой доли файлов, удаление не выполняется: так выглядит отключившийся диск с почтой, а не обычная очистка. Администратор видит предупреждение и кнопку «Разрешить удаление». Мелкие чистки (до 100 файлов) не блокируются. 100 — без защиты.

- **Рекомендация:** 50. Если почти у всех ящиков срок хранения — несколько дней, поднимите до 70–80.
- **Пример:** `50`
- **По умолчанию:** `50`

### Одновременных отправок  
`replica.parallel`

Сколько файлов отправлять одновременно в сетевую папку или S3. Писем много и они мелкие — скорость упирается в задержку сети, а не в канал, поэтому параллельность ускоряет копию в разы.

- **Рекомендация:** 4–8 для S3, 2–4 для сетевой папки.
- **Пример:** `4`
- **По умолчанию:** `4`

### Полная сверка раз в, дней  
`replica.verify_every_days`

Обычный прогон отправляет только новое — по записям о том, что уже отправлено. Раз в N дней список файлов в самой копии сверяется с архивом целиком: так находятся файлы, пропавшие или испорченные на стороне копии. 0 — не сверять (не рекомендуется). Для rsync сверка идёт всегда.

- **Рекомендация:** 7.
- **Пример:** `7`
- **По умолчанию:** `7`

### Таймаут сети, секунд  
`replica.timeout_s`

Сколько ждать ответа сервера копии (S3, SSH) на одну операцию.

- **Рекомендация:** 120.
- **Пример:** `120`
- **По умолчанию:** `120`

### Папка для копии  
`replica.dir_path`

Абсолютный путь к смонтированной сетевой папке или диску, например /mnt/backup/mailarchiver. Папка должна быть пустой (или уже содержать копию этого архива): в ней появится метка .mailarchiver-replica, и если сетевой диск отвалится, служба не станет писать копию в пустую точку монтирования. Двоеточия в именах писем записываются как %3A — SMB и NTFS их не принимают.

- **Рекомендация:** Отдельная подпапка на файловом сервере, смонтированная через /etc/fstab (cifs или nfs).
- **Пример:** `/mnt/backup/mailarchiver`
- **По умолчанию:** `(пусто)`

### Сервер и папка (SSH)  
`replica.rsync_dest`

Куда копировать rsync-ом: пользователь@сервер:/путь. Нужны вход по SSH-ключу (кнопка «Создать SSH-ключ» покажет открытый ключ для ~/.ssh/authorized_keys на сервере-получателе) и rsync на обоих серверах. Ключ сервера-получателя запоминается при первом подключении — подмена сервера потом будет замечена.

- **Рекомендация:** Отдельный пользователь без прав администратора на сервере-получателе.
- **Пример:** `backup@nas.local:/srv/mailarchiver`
- **По умолчанию:** `(пусто)`

### Порт SSH  
`replica.ssh_port`

Порт SSH сервера-получателя.

- **Рекомендация:** 22, если не меняли.
- **Пример:** `22`
- **По умолчанию:** `22`

### Файл SSH-ключа  
`replica.ssh_key_file`

Закрытый ключ для входа на сервер-получатель (без пароля; читается службой). Пусто — ключ службы replica_ssh_key в каталоге данных (его создаёт кнопка «Создать SSH-ключ»).

- **Рекомендация:** Оставьте пустым и создайте ключ кнопкой.
- **Пример:** `/etc/mailarchiver/replica_key`
- **По умолчанию:** `(пусто)`

### Ограничение скорости (SSH), КБ/с  
`replica.bwlimit_kbps`

Не занимать канал целиком при копировании rsync-ом. 0 — без ограничения.

- **Рекомендация:** 0, если копия идёт ночью.
- **Пример:** `20000`
- **По умолчанию:** `0`

### Адрес S3-хранилища  
`replica.s3_endpoint`

Адрес API хранилища.

- **Рекомендация:** Yandex Object Storage: https://storage.yandexcloud.net; VK Cloud: https://hb.ru-msk.vkcloud-storage.ru; MinIO: адрес вашего сервера MinIO.
- **Пример:** `https://storage.yandexcloud.net`
- **По умолчанию:** `(пусто)`

### Регион S3  
`replica.s3_region`

Регион хранилища — участвует в подписи запросов.

- **Рекомендация:** Yandex: ru-central1; VK Cloud: ru-msk; MinIO: us-east-1 (если не меняли).
- **Пример:** `ru-central1`
- **По умолчанию:** `ru-central1`

### Бакет S3  
`replica.s3_bucket`

Имя бакета. Бакет создаётся заранее в консоли хранилища.

- **Рекомендация:** Отдельный бакет для архива, без публичного доступа, с включённым версионированием.
- **Пример:** `company-mail-archive`
- **По умолчанию:** `(пусто)`

### Папка в бакете  
`replica.s3_prefix`

Префикс ключей внутри бакета: копия ляжет в «папку» с этим именем.

- **Рекомендация:** mailarchiver/.
- **Пример:** `mailarchiver/`
- **По умолчанию:** `mailarchiver/`

### Идентификатор ключа S3  
`replica.s3_access_key`

Идентификатор статического ключа доступа сервисного аккаунта (Access Key ID).

- **Рекомендация:** Сервисный аккаунт с правами только на этот бакет (у Yandex — роль storage.editor на бакет).
- **Пример:** `YCAJE…`
- **По умолчанию:** `(пусто)`

### Секретный ключ S3  
`replica.s3_secret_key`

Секретная часть ключа доступа (Secret Access Key). Хранится в базе в зашифрованном виде.

- **Рекомендация:** Выдаётся один раз при создании ключа — сохраните его и в менеджере паролей.
- **Пример:** `(секрет)`
- **По умолчанию:** `(пусто)`

### Бакет в пути адреса  
`replica.s3_path_style`

Адресовать бакет в пути (https://сервер/бакет/ключ), а не в имени сервера (https://бакет.сервер/ключ). MinIO понимает только первый вариант, Yandex и VK — оба, AWS для новых бакетов — только второй.

- **Рекомендация:** Включено для Yandex, VK Cloud и MinIO; выключено для AWS.
- **Пример:** `true`
- **По умолчанию:** `true`

### Класс хранилища S3  
`replica.s3_storage_class`

Класс хранения объектов. Пусто — по умолчанию (стандартное). «Холодное» хранилище дешевле хранить и дороже читать — подходит для копии, которую читают только при аварии.

- **Рекомендация:** Yandex: COLD; AWS: STANDARD_IA. Пусто — если не уверены.
- **Пример:** `COLD`
- **По умолчанию:** `(пусто)`

### Проверять сертификат S3  
`replica.s3_verify_ssl`

Проверять TLS-сертификат хранилища. Выключайте только для своего MinIO с самоподписанным сертификатом.

- **Рекомендация:** Включено.
- **Пример:** `true`
- **По умолчанию:** `true`

## 📤 Экспорт (PST и др.)

### Движок экспорта по умолчанию  
`export.default_engine`

Какой движок использовать по умолчанию: auto (сам выберет), aspose (надёжный .pst, нужна лицензия), native (встроенный .pst, экспериментальный), mbox, eml.

- **Рекомендация:** auto. Для .pst он выберет Aspose при наличии лицензии, иначе встроенный. Самый надёжный бесплатный вариант — eml/mbox.
- **Пример:** `auto`
- **По умолчанию:** `auto`

### Формат PST  
`export.pst_format`

unicode — для Outlook 2003 и новее (рекомендуется, большой объём). ansi — для Outlook 97–2002 (лимит 2 ГБ). Встроенный (native) движок создаёт ANSI.

- **Рекомендация:** unicode для современных версий Outlook. ansi только для очень старого Outlook (до 2003).
- **Пример:** `unicode`
- **По умолчанию:** `unicode`

### Разбивать PST по, МБ  
`export.pst_split_size_mb`

Разбивать большой .pst на части заданного размера (0 — не разбивать).

- **Рекомендация:** 0. Для ANSI-формата держите итоговый файл под 2 ГБ.
- **Пример:** `0`
- **По умолчанию:** `0`

### Путь к лицензии Aspose  
`export.aspose_license_path`

Путь к файлу лицензии Aspose.Email (.lic). Без лицензии Aspose работает в демо-режиме: не более 50 писем на папку и водяные знаки.

- **Рекомендация:** Укажите для промышленного использования Aspose. Иначе используйте native/eml/mbox.
- **Пример:** `/etc/mailarchiver/Aspose.Email.lic`
- **По умолчанию:** `(пусто)`

### Хранить готовые выгрузки, дней  
`export.keep_days`

Файлы экспорта старше этого срока удаляются автоматически при ежедневном обслуживании, чтобы выгрузки не заняли весь диск (полный диск останавливает копирование всех ящиков). 0 — не удалять.

- **Рекомендация:** 7–30 дней: выгрузку обычно скачивают сразу.
- **Пример:** `30`
- **По умолчанию:** `30`

## 📈 Мониторинг (Prometheus, Zabbix)

### Метрики для Prometheus и Zabbix  
`monitoring.metrics_enabled`

Отдавать состояние службы по адресу /metrics в формате Prometheus: ящики по состояниям, давность последней копии каждого ящика, очередь заданий, место на диске, копия вне сервера, снимки базы, неудачные входы. Zabbix читает этот формат элементом «HTTP-агент» с предобработкой «Prometheus pattern».

- **Рекомендация:** Включите, если в организации есть Prometheus или Zabbix: тревога придёт сама.
- **Пример:** `true`
- **По умолчанию:** `false`

### Токен доступа к метрикам  
`monitoring.metrics_token`

Секрет, который система мониторинга передаёт в заголовке «Authorization: Bearer <токен>». Не короче 16 символов; хранится в базе зашифрованным и после сохранения не показывается. Без токена метрики доступны только с адресов из списка ниже.

- **Рекомендация:** Нажмите «Создать токен», сохраните настройки и перенесите токен в Prometheus/Zabbix.
- **Пример:** `(случайная строка)`
- **По умолчанию:** `(пусто)`

### Адреса без токена  
`monitoring.metrics_allowed_ips`

С каких адресов (или сетей) метрики отдаются без токена. По умолчанию — только с самого сервера. Метрики содержат названия ящиков и адреса почты — не открывайте их всем.

- **Рекомендация:** Адрес сервера Prometheus/Zabbix или оставьте только 127.0.0.1 и используйте токен.
- **Пример:** `127.0.0.1, 10.0.0.15`
- **По умолчанию:** `127.0.0.1, ::1`

### Метрики по каждому ящику  
`monitoring.per_account_metrics`

Отдавать дату последней удачной копии, итог входа, число писем и объём по КАЖДОМУ ящику (подписи: номер, название, логин). На 500+ ящиках это несколько тысяч рядов — Prometheus справляется, но если нужны только общие цифры, выключите.

- **Рекомендация:** Включено: так тревога называет конкретный ящик.
- **Пример:** `true`
- **По умолчанию:** `true`

## 👥 Сотрудники

### Синхронизация по расписанию  
`employees.sync_enabled`

Регулярно сверять справочник сотрудников с файлом-выгрузкой из кадровой системы: новые сотрудники добавляются, у существующих обновляются должность, отдел и телефон. Уволенные (те, кто пропал из файла) НЕ отключаются и не удаляются — это делает администратор вручную.

- **Рекомендация:** Включайте, когда путь к файлу задан и пробная синхронизация кнопкой «Синхронизировать» прошла без ошибок.

- **По умолчанию:** `false`

### Источник списка  
`employees.source_type`

Откуда брать список сотрудников: «Файл на сервере» — служба читает CSV/XLSX по пути на диске; «Адрес (URL)» — служба сама скачивает выгрузку по ссылке http(s) при каждой синхронизации.

- **Рекомендация:** URL удобнее, когда кадровая система умеет отдавать выгрузку ссылкой: файл не нужно копировать на сервер архива.
- **Пример:** `file`
- **По умолчанию:** `file`

### Файл-источник  
`employees.source_file`

Путь на сервере к файлу со списком сотрудников (CSV или XLSX); используется, когда источник — «Файл на сервере». Первая строка — заголовки: ФИО, E-mail, Должность, Отдел, Телефон, Табельный номер. Кодировка и разделитель определяются автоматически.

- **Рекомендация:** Положите выгрузку в отдельный каталог, куда кадровая система кладёт файл по расписанию. Формат файла можно посмотреть, скачав образец в разделе «Сотрудники».
- **Пример:** `/var/lib/mailarchiver/hr/employees.csv`
- **По умолчанию:** `(пусто)`

### Адрес выгрузки (URL)  
`employees.source_url`

Ссылка http:// или https://, по которой отдаётся файл со списком сотрудников (CSV или XLSX). Используется, когда источник — «Адрес (URL)». Содержимое и заголовки ответа проверяются: если по ссылке придёт страница входа, синхронизация об этом прямо скажет.

- **Рекомендация:** Спросите у администратора кадровой системы прямую ссылку на выгрузку. Внутри организации обычно достаточно https-адреса без дополнительных ключей.
- **Пример:** `https://hr.example.ru/export/employees.csv`
- **По умолчанию:** `(пусто)`

### Логин источника  
`employees.source_url_user`

Имя пользователя для HTTP Basic, если выгрузка закрыта паролем. Оставьте пустым для открытой ссылки.

- **Рекомендация:** Заводите для архива отдельную учётную запись «только чтение» — так её можно отозвать, не трогая остальных.
- **Пример:** `mailarchiver`
- **По умолчанию:** `(пусто)`

### Пароль источника  
`employees.source_url_password`

Пароль HTTP Basic к адресу выгрузки. Хранится в базе в зашифрованном виде и не показывается в интерфейсе. Пустое поле при сохранении означает «оставить прежний пароль».

- **Рекомендация:** Заполняйте только если сервер-источник действительно требует авторизацию.
- **Пример:** `(скрыт)`
- **По умолчанию:** `(пусто)`

### Проверять сертификат источника  
`employees.source_url_verify_ssl`

Проверять TLS-сертификат сервера, с которого скачивается выгрузка. Выключение делает соединение уязвимым к подмене — оставляйте включённым, пока это возможно.

- **Рекомендация:** Выключайте только для внутреннего сервера с самоподписанным сертификатом, когда выпустить доверенный нельзя.
- **Пример:** `true`
- **По умолчанию:** `true`

### Таймаут загрузки, с  
`employees.source_url_timeout_s`

За сколько секунд выгрузка должна скачаться ЦЕЛИКОМ (соединение, ответ сервера и все данные). Обрыв или неполный ответ отвергаются — частичный список не применяется.

- **Рекомендация:** 60 с хватает почти всегда. Увеличьте до 180–300, если кадровая система формирует выгрузку прямо в момент запроса.
- **Пример:** `60`
- **По умолчанию:** `60`

### Формат ответа  
`employees.source_url_format`

Чем разбирать скачанное: «Определять автоматически» (по заголовку Content-Disposition, расширению в ссылке и содержимому), «CSV» или «Excel (XLSX)».

- **Рекомендация:** Оставьте автоматически. Задавайте формат явно, если ссылка вида /export?id=5 не содержит имени файла и определение ошибается.
- **Пример:** `auto`
- **По умолчанию:** `auto`

### Когда синхронизировать  
`employees.cron`

Cron-выражение из пяти полей: минуты часы день месяц день_недели. «0 5 * * *» — каждый день в 05:00, «0 5 * * 1» — по понедельникам в 05:00.

- **Рекомендация:** Ночью или рано утром, уже после того как кадровая система обновит файл.
- **Пример:** `0 5 * * *`
- **По умолчанию:** `0 5 * * *`

### Заводить ящики новым сотрудникам  
`employees.create_accounts`

Создавать почтовый ящик для НОВОГО сотрудника, у которого в файле указан e-mail. Ящик создаётся ВЫКЛЮЧЕННЫМ и без пароля: копирование не начнётся, пока администратор не впишет пароль и не включит ящик. Если ящик с таким логином уже есть, он просто привязывается. Нужен «IMAP-сервер новых ящиков»: без него ящики не заводятся. Ящик, который администратор удалил или отвязал, заново не создаётся.

- **Рекомендация:** Оставьте включённым: карточка сотрудника сразу связана с ящиком, останется только задать пароль.
- **Пример:** `true`
- **По умолчанию:** `true`

### IMAP-сервер новых ящиков  
`employees.account_host`

Адрес почтового сервера, который подставляется в автоматически создаваемые ящики сотрудников. Пока он не задан, ящики сотрудникам не заводятся (карточки при этом обновляются).

- **Рекомендация:** Укажите корпоративный почтовый сервер — тот же, что в остальных ящиках. Иначе поле придётся заполнять руками у каждого нового сотрудника.
- **Пример:** `imap.example.ru`
- **По умолчанию:** `(пусто)`

### Порт новых ящиков  
`employees.account_port`

Порт IMAP для создаваемых ящиков: 993 — SSL/TLS, 143 — STARTTLS или без шифрования.

- **Рекомендация:** 993 вместе с шифрованием SSL/TLS.
- **Пример:** `993`
- **По умолчанию:** `993`

### Шифрование новых ящиков  
`employees.account_security`

Режим защиты соединения для создаваемых ящиков: ssl (обычно порт 993), starttls (обычно 143) или plain (без шифрования, не рекомендуется).

- **Рекомендация:** ssl — стандартный выбор для корпоративной почты.
- **Пример:** `ssl`
- **По умолчанию:** `ssl`

### Название ящика (шаблон)  
`employees.account_name_template`

Как называть создаваемый ящик в списке. Доступны подстановки: {full_name} — ФИО, {last_name} — фамилия, {first_name} — имя, {email} — адрес, {local} — часть адреса до «@», {domain} — после «@», {position} — должность, {department} — отдел, {external_id} — табельный номер. Пустые значения и оставшиеся от них скобки убираются автоматически.

- **Рекомендация:** «{full_name}» — понятно в списке ящиков. «{full_name} ({department})» удобно, когда однофамильцы работают в разных отделах.
- **Пример:** `{full_name} ({department})`
- **По умолчанию:** `{full_name}`

### Логин ящика (шаблон)  
`employees.account_username_template`

Имя пользователя для входа на IMAP-сервер. Подстановки те же, что в названии. По умолчанию логин равен адресу сотрудника.

- **Рекомендация:** Оставьте «{email}». Меняйте, если на сервере входят коротким именем: тогда подойдёт «{local}» или «{local}@corp.local».
- **Пример:** `{local}`
- **По умолчанию:** `{email}`

### Заметка в карточке ящика (шаблон)  
`employees.account_notes_template`

Текст, который записывается в поле «Заметки» созданного ящика. Подстановки те же. Помогает потом понять, откуда взялся ящик.

- **Рекомендация:** Добавьте отдел и должность — «Создан автоматически: {position}, {department}»: по заметке сразу видно владельца.
- **Пример:** `Создан автоматически: {position}, {department}`
- **По умолчанию:** `Создан автоматически для сотрудника.`

### Включать созданные ящики  
`employees.account_enabled`

Включать ящик сразу при создании. Пароль шаблон не задаёт: пока администратор не впишет пароль, копирование всё равно не начнётся, но включённый ящик сразу попадёт в расписания и отчёты.

- **Рекомендация:** Выключено — так список ящиков не заполняется записями, которые заведомо не подключаются. Включайте, если пароли задаются массово сразу после синхронизации.
- **Пример:** `false`
- **По умолчанию:** `false`

### Копировать только папки  
`employees.account_folder_include`

Список папок через запятую, которые будут копироваться у создаваемых ящиков. Пусто — копировать все папки.

- **Рекомендация:** Оставьте пустым: для архива обычно нужна вся почта. Заполняйте, когда по регламенту хранится только «Входящие» и «Отправленные».
- **Пример:** `INBOX, Отправленные`
- **По умолчанию:** `(пусто — все папки)`

### Пропускать папки  
`employees.account_folder_exclude`

Список папок через запятую, которые у создаваемых ящиков копироваться не будут (например «Спам» и «Корзина»).

- **Рекомендация:** «Спам, Корзина, Junk, Trash» — экономит место и время без потери нужной переписки.
- **Пример:** `Спам, Корзина`
- **По умолчанию:** `(пусто)`

### Срок хранения новых ящиков, дней  
`employees.account_retention_days`

Сколько дней хранить письма в архиве такого ящика: -1 — как задано в общих настройках раздела «Хранение и очистка», 0 — хранить вечно, N — N дней.

- **Рекомендация:** -1: пусть срок задаётся в одном месте — общими настройками.
- **Пример:** `-1`
- **По умолчанию:** `-1`

### Заводить расписание копирования  
`employees.account_schedule_enabled`

Создавать новому ящику расписание регулярного копирования. Без него ящик появится в списке, но копироваться не будет, пока администратор не добавит расписание вручную.

- **Рекомендация:** Включите: иначе почта новых сотрудников не архивируется, и это обнаруживается только когда письма уже нужны.
- **Пример:** `true`
- **По умолчанию:** `false`

### Расписание новых ящиков  
`employees.account_schedule_cron`

Cron-выражение из пяти полей для создаваемого расписания: минуты часы день месяц день_недели. «0 2 * * *» — каждую ночь в 02:00.

- **Рекомендация:** Ночью, вразнобой с синхронизацией сотрудников: сначала появляются ящики, затем копируется почта.
- **Пример:** `0 2 * * *`
- **По умолчанию:** `0 2 * * *`

### Входить в новые ящики через администратора  
`employees.account_use_master`

Заводить ящики сотрудников со способом входа «через администратора почты» — тогда им не нужны пароли. Работает, только если включён вход через администратора и его сервер совпадает с сервером в шаблоне.

- **Рекомендация:** Включите, если настроили и проверили вход через администратора.
- **Пример:** `true`
- **По умолчанию:** `false`

### Отмечать уволенных по выгрузке  
`employees.dismiss_from_file`

Если сотрудник, уже заведённый в справочнике, помечен в выгрузке как не работающий (колонки «Работает: нет», «Уволен: да» или прошедшая «Дата увольнения»), карточка отмечается уволенной: архив его ящика удерживается, копирование выключается после последней копии (см. ниже). Если он снова числится работающим — всё возвращается. Защита: если одна выгрузка отмечает уволенными больше 20 % сотрудников, увольнения не применяются (похоже на испорченный файл).

- **Рекомендация:** Включено, если выгрузка кадров надёжная.
- **Пример:** `true`
- **По умолчанию:** `true`

### Уволен, если нет в выгрузке, дней  
`employees.dismiss_missing_days`

Считать уволенным сотрудника (из синхронизации), которого нет в выгрузке больше N дней подряд. Подходит, если выгрузка содержит только работающих. 0 — не считать.

- **Рекомендация:** 0, если в выгрузке есть отметка об увольнении; иначе 14–30.
- **Пример:** `30`
- **По умолчанию:** `0`

### Что делать с ящиком уволенного  
`employees.dismissed_action`

«Последняя копия и выключить» — сразу поставить копирование ящика в очередь (пока ящик ещё есть на сервере), после него выключить копирование. «Продолжать копировать» — только удерживать архив.

- **Рекомендация:** Последняя копия и выключить.
- **Пример:** `final_backup_disable`
- **По умолчанию:** `final_backup_disable`

### Хранить архив уволенного, лет  
`employees.dismissed_keep_years`

Сколько лет архив уволенного сотрудника удерживается: письма не удаляются по сроку хранения, даже если у ящика срок «3 дня». Когда удержание истечёт, ящик попадёт в отбор «Удержание истекло» — удалить его архив можно вручную (сам архив автоматически не удаляется). 0 — бессрочно.

- **Рекомендация:** По внутренним правилам организации; часто 3–5 лет.
- **Пример:** `5`
- **По умолчанию:** `5`

## 🔎 Поиск по письмам

### Поиск по письмам  
`search.enabled`

Индексировать письма, чтобы искать их в разделе «Почта»: по теме, отправителю и получателям, именам вложений и тексту — в одном ящике или во всех сразу. Новые письма индексируются в фоне; первое индексирование большого архива идёт долго (каждое письмо читается один раз), поиск по уже проиндексированной части работает сразу.

- **Рекомендация:** Включено.
- **Пример:** `true`
- **По умолчанию:** `true`

### Искать по тексту писем  
`search.index_bodies`

Индексировать и текст писем (без цитат прошлых писем в переписке). Индекс занимает место в базе примерно в размере проиндексированного текста. Выключено — поиск только по теме, адресам и именам вложений.

- **Рекомендация:** Включено, если на диске с базой есть место.
- **Пример:** `true`
- **По умолчанию:** `true`

### Текст писем в индексе при шифровании  
`search.index_bodies_encrypted`

При включённом шифровании копии текст писем по умолчанию НЕ индексируется: индекс хранится в базе открыто и раскрыл бы то, что прячет шифрование. Включите, только если база данных защищена так же, как ключ шифрования.

- **Рекомендация:** Выключено.
- **Пример:** `false`
- **По умолчанию:** `false`

### Текста письма в индексе, КБ  
`search.body_max_kb`

Сколько текста одного письма индексировать. Длинные рассылки и выгрузки обрезаются.

- **Рекомендация:** 16 — обычное письмо целиком.
- **Пример:** `16`
- **По умолчанию:** `16`

## 🗝️ Вход в ящики через администратора почты

### Входить в ящики через администратора  
`mailadmin.enabled`

Копировать ящики, не зная паролей сотрудников: служба входит учётной записью администратора почты «от имени» ящика. Так не нужно собирать и обновлять сотни паролей. Работает, только если почтовый сервер это умеет: Dovecot (master users), Cyrus, Zimbra (SASL PLAIN с authzid). Axigen такой вход в документации не описывает — проверьте кнопкой «Проверить вход администратора»; если сервер откажет, оставьте вход по паролям. Ящикам с входом через администратора пароль не нужен (в карточке ящика — «Способ входа: через администратора почты»).

- **Рекомендация:** Включайте, если сервер поддерживает такой вход, и используйте отдельную учётную запись только для архива.
- **Пример:** `true`
- **По умолчанию:** `false`

### Сервер администратора  
`mailadmin.host`

IMAP-сервер, для которого действует вход администратора. Пароль администратора отправляется ТОЛЬКО на этот сервер — ящик с другим адресом (опечатка или чужой сервер) его не получит.

- **Рекомендация:** Тот же адрес, что у ящиков, например mx.company.ru.
- **Пример:** `mx.company.ru`
- **По умолчанию:** `(пусто)`

### Логин администратора почты  
`mailadmin.user`

Учётная запись, которой сервер разрешает входить в чужие ящики (master user в Dovecot, администратор в Cyrus/Zimbra).

- **Рекомендация:** Отдельная учётная запись для архива с правом только на чтение, если сервер так умеет.
- **Пример:** `archive-master`
- **По умолчанию:** `(пусто)`

### Пароль администратора почты  
`mailadmin.password`

Пароль этой учётной записи. Хранится в базе в зашифрованном виде и наружу не отдаётся.

- **Рекомендация:** Длинный уникальный пароль.
- **Пример:** `(пароль)`
- **По умолчанию:** `(пусто)`

### Способ входа администратора  
`mailadmin.mode`

«SASL PLAIN с authzid» — стандартный способ (RFC 4616): сервер проверяет пароль администратора и открывает ящик пользователя (Dovecot, Cyrus, Zimbra). «Логин с разделителем» — вход вида ящик*администратор (Dovecot с auth_master_user_separator).

- **Рекомендация:** SASL PLAIN; если сервер его не принимает — логин с разделителем.
- **Пример:** `sasl_plain`
- **По умолчанию:** `sasl_plain`

### Разделитель  
`mailadmin.separator`

Для входа «с разделителем»: символ между адресом ящика и логином администратора (в Dovecot — auth_master_user_separator).

- **Рекомендация:** «*».
- **Пример:** `*`
- **По умолчанию:** `*`

## 📬 Поля почтового ящика

### Название (`name`)

Произвольное имя ящика для отображения в интерфейсе.

- **Рекомендация:** Понятное имя, напр. «Почта директора» или «info@company».
- **Пример:** `Основная почта`

### IMAP-сервер (`host`)

Адрес IMAP-сервера почтового провайдера.

- **Рекомендация:** Смотрите в справке провайдера. Примеры: imap.yandex.ru, imap.mail.ru, imap.gmail.com, outlook.office365.com.
- **Пример:** `imap.yandex.ru`

### Порт (`port`)

Порт IMAP. 993 — SSL/TLS (обычный выбор), 143 — STARTTLS/без шифрования.

- **Рекомендация:** 993 для SSL/TLS.
- **Пример:** `993`

### Логин (`username`)

Имя пользователя для входа в почту (обычно полный адрес).

- **Рекомендация:** Полный адрес, напр. user@yandex.ru.
- **Пример:** `user@yandex.ru`

### Пароль (`password`)

Пароль для доступа по IMAP. Хранится в БД в зашифрованном виде (ключом сервиса).

- **Рекомендация:** Для Яндекс/Mail.ru/Gmail включите IMAP и создайте «пароль приложения» — обычный пароль часто не подходит.
- **Пример:** `(пароль приложения)`

### Шифрование (`security`)

SSL/TLS (порт 993) — рекомендуется. STARTTLS (порт 143). Без шифрования — только для локальных серверов.

- **Рекомендация:** SSL/TLS.
- **Пример:** `SSL/TLS (993)`

### Способ входа (`auth_type`)

«Пароль» — обычный логин/пароль. «OAuth2» — для Gmail и Microsoft 365, где вход по паролю отключён. «Через администратора почты» — пароль ящика не нужен: служба входит учётной записью администратора (настраивается в «Настройки → Вход в ящики через администратора почты»; сервер должен это поддерживать).

- **Рекомендация:** «Пароль» для большинства. «OAuth2» для Gmail/Microsoft 365.
- **Пример:** `Пароль`

### Исключить папки (`folder_exclude`)

Папки, которые не нужно копировать для этого ящика (в дополнение к глобальным настройкам).

- **Рекомендация:** Например, спам и корзина.
- **Пример:** `Спам, Корзина`

### OAuth2 Client ID (`oauth_client_id`)

Идентификатор клиентского приложения OAuth2 (из консоли Google/Microsoft).

- **Рекомендация:** Создайте OAuth-приложение у провайдера, разрешите доступ к почте (IMAP).
- **Пример:** `1234-abcd.apps.googleusercontent.com`

### OAuth2 Client Secret (`oauth_client_secret`)

Секрет клиентского приложения OAuth2.

- **Рекомендация:** Из той же консоли провайдера.
- **Пример:** `(секрет)`

### OAuth2 Refresh Token (`oauth_refresh_token`)

Долгоживущий токен обновления, полученный при первичной авторизации приложения.

- **Рекомендация:** Получите его один раз через процедуру OAuth2 вашего провайдера.
- **Пример:** `(токен)`

### OAuth2 Token URL (`oauth_token_url`)

Адрес сервиса выдачи токенов провайдера.

- **Рекомендация:** Google: https://oauth2.googleapis.com/token; Microsoft: https://login.microsoftonline.com/common/oauth2/v2.0/token.
- **Пример:** `https://oauth2.googleapis.com/token`
