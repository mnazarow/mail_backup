# Шифрование локальной копии писем

Если включить шифрование, каждое письмо в каталоге данных хранится в
зашифрованном виде (файлы `*.enc`). Украденный диск, резервная копия каталога
данных или случайно открытый доступ к папке писем тогда ничего не раскрывают —
без ключа письма не прочитать.

Всё остальное работает как прежде: просмотр писем в интерфейсе, скачивание
`.eml` и вложений, экспорт в PST/EML/MBOX, восстановление на сервер — служба
расшифровывает письма «на лету», потоком, не выкладывая открытый текст на диск.

## Как это устроено

- Алгоритм — **AES-256-GCM**. Главный ключ — 32 случайных байта в отдельном
  файле (64 шестнадцатеричных символа).
- Для каждого письма из главного ключа и случайной соли выводится **собственный
  ключ файла** (HKDF-SHA256), поэтому миллионы писем под одним главным ключом
  безопасны.
- Письмо шифруется порциями по 64 КБ, у каждой — своя проверка подлинности:
  подмена, перестановка или обрезка любой порции обнаруживается при чтении
  («файл повреждён» вместо тихо испорченного письма). Крупные письма читаются
  потоком и не занимают память целиком.
- В заголовке файла записан отпечаток ключа: если подложить не тот ключ, служба
  сразу скажет «ключ не подходит», а не выдаст мусор.
- Письма, сохранённые **до** включения шифрования, остаются открытыми, пока вы
  не запустите их перешифровку (см. ниже).

## Включение

**Способ 1 — ключ создаёт служба (проще).** В «Настройки → Хранилище» включите
«Шифровать письма». Если путь к ключу не задан, служба создаст ключ
`storage.key` в каталоге данных и покажет его путь. **Сразу скопируйте этот
файл в надёжное место вне сервера** — иначе шифрование защищает только от
утечки отдельной папки писем, но не от кражи всего каталога данных вместе с
ключом.

**Способ 2 — ключ вне каталога данных (надёжнее).**

```bash
sudo mailarchiver storage-key --generate /etc/mailarchiver/storage.key
sudo chown root:mailarchiver /etc/mailarchiver/storage.key && sudo chmod 640 /etc/mailarchiver/storage.key
```

Затем в `config.yaml` (или в «Настройки → Хранилище»):

```yaml
storage:
  encrypt: true
  encryption_key_file: "/etc/mailarchiver/storage.key"
```

и перезапустите службу: `sudo systemctl restart mailarchiver`. Копию ключа
сохраните отдельно (менеджер паролей, флешка в сейфе).

Проверить состояние в любой момент (ничего не создаёт и не меняет):

```bash
sudo mailarchiver storage-key
```

Команда покажет путь и отпечаток ключа, ожидаемый отпечаток (которым шифровался
архив), сколько писем зашифровано и предупредит, если права на файл ключа
слишком открытые.

## Зашифровать уже сохранённые письма

«Настройки → Хранилище» → блок «Шифрование копии» → «Зашифровать уже
сохранённые (N)». Для каждого ящика ставится задание «Шифрование копии»;
прогресс — в «Очередь и задания». Прерванная перешифровка безопасна: при
повторном запуске она продолжится, а «двойники» писем от прерванного прогона
удаляются, только если оба файла читаются и совпадают с индексом.

Обратная операция — «Расшифровать все» — доступна, когда шифрование выключено.

> **Карантинные копии** (каталоги `account_N_old_…`, остающиеся после «Скопировать
> заново») не перешифровываются. Итог задания об этом предупреждает — удалите их
> в карточке ящика («Прежние копии»), когда убедитесь, что они не нужны.

## Если ключ пропал

Шифрование работает по принципу «закрыто при сбое»:

- если шифрование включено, а ключ не найден или не подходит, служба **не
  сохраняет новые письма** (иначе они легли бы на диск открытым текстом);
  копирование ящиков завершается ошибкой, а на дашборде появляется красная
  плашка «Копирование остановлено: нет ключа шифрования»;
- уже зашифрованные письма в интерфейсе не открываются («Письмо зашифровано, а
  ключ шифрования не загружен»).

Что делать: верните файл ключа на место (из резервной копии) и перезапустите
службу. Если ключ утерян безвозвратно, зашифрованные письма восстановить
невозможно — ни нами, ни кем-либо ещё. Поэтому **копия ключа отдельно от
сервера обязательна**.

## Перенос на другой сервер

Скопируйте каталог данных **и** файл ключа (если он лежит вне каталога данных —
например в `/etc/mailarchiver/`), а также `config.yaml`. Проверьте на новом
сервере `sudo mailarchiver storage-key`: отпечаток ключа должен совпасть с
ожидаемым.
