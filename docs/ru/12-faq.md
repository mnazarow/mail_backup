# 12. Частые вопросы (FAQ)

**Это удалит письма с почтового сервера?**
Нет. Копирование только читает письма. Локальная копия — надёжный архив, из которого ничего не
пропадает, даже если письмо удалят на сервере. Локальные письма удаляются только по сроку хранения,
который вы задали сами (общий — «Настройки → Хранение и очистка», или свой срок у ящика).

**Сколько ящиков можно подключить?**
Ограничений нет (в работе — архивы на сотни ящиков). Сколько заданий идёт одновременно, задаёт
`backup.max_concurrent_jobs` (1–16); с одним ящиком одновременно работает только одно задание.

**Нужен ли интернет для экспорта в PST?**
Нет, экспорт локальный. Интернет нужен только при первичной установке библиотеки Aspose и для OAuth2.

**Где лежат копии писем?**
В каталоге данных: по умолчанию `/var/lib/mailarchiver/mailboxes` (в Docker — том `/data`). Это
обычные файлы `.eml` в структуре папок Maildir.

**Можно ли перенести копии на другой сервер?**
Да. Скопируйте каталог данных целиком (в нём письма, база индексов и `secret.key`), `config.yaml` и —
если включено шифрование и ключ лежит вне каталога данных — **файл ключа шифрования** (например
`/etc/mailarchiver/storage.key`). Без него зашифрованные письма на новом сервере не прочитать.
Установите MailArchiver, укажите тот же каталог данных и проверьте: `sudo mailarchiver storage-key`.

**А если сервер сгорит целиком?**
Включите копию архива вне сервера — в сетевую папку, на другой сервер по SSH или в S3-хранилище
(«Настройки → Копия вне сервера»). Она обновляется каждый день и включает снимки базы. Как
восстановиться из неё — [13-replica.md](13-replica.md). Ключи (`secret.key` и ключ шифрования)
храните отдельно от копии.

**Как узнать, что копирование сломалось, не заходя в интерфейс?**
Включите еженедельную сводку на почту и/или метрики для Prometheus и Zabbix —
[14-monitoring.md](14-monitoring.md).

**Можно ли найти письмо сразу во всех ящиках?**
Да: строка поиска в разделе «Почта», вариант «во всех ящиках» — [15-search.md](15-search.md).
Каждый такой поиск записывается в аудит.

**Можно ли не собирать пароли сотрудников?**
Если почтовый сервер умеет пускать администратора в чужие ящики (Dovecot, Cyrus, Zimbra) — да,
см. [16-mailadmin.md](16-mailadmin.md). Axigen такой вход не документирует — проверьте кнопкой
«Проверить вход администратора»; если не работает, остаются пароли ящиков.

**Что будет с почтой уволенного сотрудника?**
Сделается последняя копия, копирование выключится, а архив будет удерживаться (не удалится по
сроку хранения) 5 лет или сколько настроено — [07-employees.md, раздел 7.8](07-employees.md).

**Много ли места занимают одинаковые вложения (рассылки, логотипы)?**
Посчитайте на своих письмах: «Аналитика → 🧬 Одинаковые вложения» —
[06-analytics.md, раздел 6.3](06-analytics.md). Формат хранения отчёт не меняет.

**Чем отличаются форматы экспорта?**
`.pst` — родной формат Outlook (открывается двойным щелчком/через «Открыть файл данных»).
`EML` — по файлу на письмо, без потерь, письма можно перетаскивать в Outlook. `MBOX` — один файл на
папку, импортируется Thunderbird и конвертерами.

**Почему встроенный экспорт PST помечен «экспериментально»?**
Формат PST закрытый и сложный; бесплатных генераторов корректного `.pst` под Linux не существует.
Встроенный движок реализует подмножество формата и проверяется на чтение утилитой `readpst`, но
Outlook строже — поэтому обязательно проверьте результат в своей версии Outlook. Вложения встроенный
движок не переносит (только папки, тему, адреса, дату и текст писем). Гарантированный путь с
вложениями — движок Aspose или форматы EML/MBOX.

**Какой формат PST выбрать для моей версии Outlook?**
Unicode — для Outlook 2003 и новее (рекомендуется). ANSI — только для Outlook 97–2002 (лимит 2 ГБ).
Формат выбирается в окне экспорта («Формат PST»).

**Безопасно ли открывать доступ из интернета?**
Только через HTTPS (reverse proxy) и с включённой аутентификацией. Прямой доступ по HTTP наружу не
рекомендуется.

**Как часто делать бэкап?**
Для большинства задач достаточно раза в сутки ночью (`0 3 * * *`). Инкрементальный бэкап быстрый, но
слишком частые запуски могут упереться в лимиты почтового сервера.

**Хранятся ли пароли ящиков в открытом виде?**
Нет. Пароли и OAuth-токены шифруются (Fernet/AES) ключом сервиса (`secret.key`). Пароли пользователей
веб-интерфейса хранятся в виде необратимого хеша (PBKDF2).

**А сами письма на диске?**
По умолчанию — обычные файлы `.eml`. Можно включить шифрование локальной копии (AES-256-GCM) —
см. [09-encryption.md](09-encryption.md).

**Как защитить вход администратора сильнее пароля?**
Включите двухфакторный вход (код из приложения на телефоне) — см. [08-security.md](08-security.md).
Сделать его обязательным для всех администраторов: «Настройки → Безопасность → Обязательный
двухфакторный вход».

**Можно ли пользоваться из командной строки?**
Да. Установщик создаёт команду `mailarchiver` (запущенная через `sudo`, она работает от имени службы):

| Команда | Что делает |
|---|---|
| `mailarchiver check-config` | проверить конфигурацию (опечатки в параметрах — предупреждения) |
| `mailarchiver create-admin -u ИМЯ` | создать администратора (`--password-file`/`--password-stdin` для скриптов) |
| `mailarchiver reset-password -u ИМЯ` | сбросить пароль пользователя |
| `mailarchiver reset-2fa -u ИМЯ` | отключить двухфакторный вход (потерян телефон) |
| `mailarchiver storage-key` | состояние ключа шифрования копии (ничего не меняет) |
| `mailarchiver storage-key --generate ПУТЬ` | создать новый ключ шифрования |
| `mailarchiver replica-ssh-key` | показать (при первом вызове — создать) SSH-ключ службы для копии по rsync |
| `mailarchiver replica-pull --to КАТАЛОГ` | скачать копию вне сервера после аварии (`--dir ПАПКА` или `--s3-…`, `--only-db`) |
| `mailarchiver restore-snapshot СНИМОК` | восстановить базу из снимка (`--key ФАЙЛ`, `--force`) |
| `mailarchiver version` | версия |

Остальное — через веб-интерфейс и REST API (схема — `/api/docs`, только для администратора).
