MailArchiver — документация

Сервис резервного копирования почтовых ящиков по IMAP с веб-интерфейсом, очередью заданий, планировщиком, подробной статистикой и экспортом копий в формат .pst для Microsoft Outlook.

Эта документация написана так, чтобы ей мог воспользоваться даже не специалист. Если вы умеете копировать команды в терминал и заполнять формы в браузере — вы справитесь. Сложные места снабжены пояснениями и подсказками.

💡 Что делает программа простыми словами Она регулярно и автоматически «скачивает» все письма из ваших почтовых ящиков и хранит их локальную копию на вашем сервере. Из этой копии можно в любой момент получить файл .pst и открыть его в Outlook, либо «залить» письма обратно на почтовый сервер, если они пропали.

Ключевые возможности

  • Резервное копирование по IMAP — инкрементальное (докачиваются только новые письма), с сохранением папок и флагов.
  • Расписание — копирование запускается автоматически (например, каждую ночь).
  • Экспорт в .pst для всех версий Outlook (ANSI для 97–2002, Unicode для 2003+), а также в EML и MBOX.
  • Восстановление писем из копии обратно на любой IMAP-сервер.
  • Импорт из .pst — залить существующий PST-файл на почтовый сервер.
  • Просмотр писем прямо в интерфейсе (папки, список, чтение с вложениями и HTML).
  • Вход по ящику — по email и паролю самого ящика; такой пользователь видит только свой ящик.
  • Хранение копий за 3 дня / 1 неделю от текущей даты (пресеты очистки на каждый ящик).
  • Веб-интерфейс с живой статистикой, очередью, логами и подсказкой к каждому параметру.
  • Очередь заданий с приоритетами, ограничением нагрузки и повторными попытками при сбоях.
  • Безопасность — вход по паролю, двухфакторный вход, защита от подбора, журнал безопасности, шифрование паролей ящиков и — по желанию — самих писем на диске.
  • Копия вне сервера — каждый день в сетевую папку, на другой сервер по SSH или в S3, со снимками базы.
  • Мониторинг — метрики для Prometheus и Zabbix, еженедельная сводка на почту.
  • Поиск по письмам во всех ящиках — по теме, адресам, вложениям и тексту.
  • Вход в ящики через администратора почты — без сбора паролей сотрудников (Dovecot, Cyrus, Zimbra).
  • Уволенные сотрудники — последняя копия, выключение копирования и удержание архива на годы.
  • Отчёт «Одинаковые вложения» — сколько места сэкономит хранение одной копии рассылок и логотипов.

2. Как это работает (методология)

MailArchiver состоит из нескольких взаимодействующих частей. Понимание общей схемы поможет настроить сервис под ваши задачи.

Резервное копирование: инкрементальный алгоритм

При копировании MailArchiver не скачивает всё заново каждый раз. Он использует стандартные механизмы IMAP:

  • у каждого письма в папке есть уникальный номер UID;
  • у папки есть признак UIDVALIDITY — если он изменился, папка перечитывается целиком (так требует протокол);
  • сервис помнит, какие UID уже сохранены, и докачивает только новые письма.

Каждое письмо сохраняется отдельным файлом в формате Maildir (стандарт, который понимают многие почтовые программы). Отдельный файл на письмо — это надёжно: повреждение одного файла не затрагивает остальные, копию легко просматривать и переносить. После записи размер и контрольная сумма (SHA-256) сверяются — это защищает от «тихой» порчи данных.

Очередь и планировщик

Любая тяжёлая операция (копирование, экспорт, восстановление) ставится в очередь и выполняется фоновыми воркерами. Это позволяет: видеть прогресс в реальном времени, не перегружать почтовый сервер (лимит одновременных подключений на ящик), безопасно повторять при сбоях. Планировщик по расписанию сам ставит задания в очередь — например, «каждый день в 3:00 сделать бэкап всех ящиков».

3. Установка

Есть два способа. Выберите один.

Способ А. Установка скриптом (служба systemd) — рекомендуется для сервера

Подходит для обычного Linux-сервера (Debian/Ubuntu, RHEL/Rocky/Alma/Fedora, openSUSE, Arch). Скрипт сам определит дистрибутив, установит зависимости, создаст службу и настроит автозапуск.

  1. Скопируйте папку проекта на сервер (например, через scp или git) и зайдите в неё: 
    cd mail_backup
  2. Запустите установку с правами администратора: 
    sudo bash scripts/install.sh
    Скрипт установит Python-зависимости в изолированное окружение, создаст пользователя mailarchiver, службу и файл настроек /etc/mailarchiver/config.yaml.
  3. В конце установки появится запрос на создание администратора — введите логин и пароль. Если установка шла без интерактивного ввода, создайте его вручную: 
    sudo -u mailarchiver /opt/mailarchiver/venv/bin/mailarchiver \
  -c /etc/mailarchiver/config.yaml create-admin
  4. Готово. Веб-интерфейс доступен на http://127.0.0.1:8493.
Полезные команды службы 
systemctl status mailarchiver     # состояние
journalctl -u mailarchiver -f      # смотреть логи в реальном времени
systemctl restart mailarchiver     # перезапуск
⚠ Доступ снаружи По умолчанию сервис слушает только 127.0.0.1 (локально) — это безопасно. Чтобы открыть доступ из сети, настройте reverse proxy (nginx/traefik) с HTTPS (см. раздел «Безопасность»), а не открывайте порт напрямую.

Способ Б. Docker Compose — самый простой

Если на сервере есть Docker, это самый быстрый путь: все зависимости уже внутри образа.

  1. Зайдите в папку docker проекта и при необходимости откройте docker-compose.yml, чтобы задать логин/пароль администратора (переменные MA_ADMIN_USER и MA_ADMIN_PASSWORD).
  2. Соберите и запустите контейнер: 
    cd docker
docker compose up -d
  3. Откройте http://ВАШ_СЕРВЕР:8493 и войдите под заданными логином/паролем.
💡 Где хранятся данные Все копии писем и настройки лежат в томе mailarchiver-data и переживают перезапуск и обновление контейнера. Экспортированные файлы можно забирать через веб-интерфейс (кнопка «Скачать») или смонтировать хост-каталог в /data/exports.

4. Первый вход

При первом открытии веб-интерфейса вам предложат создать администратора (если он ещё не создан). Затем — обычная форма входа.

⚠ Первичную настройку откройте по IP-адресу Мастер создания первого администратора работает, только если интерфейс открыт по IP-адресу, localhost, короткому имени без точки или по имени из «Внешний URL» (server.public_url). Это защита от атаки DNS rebinding: чужой сайт не сможет создать администратора раньше вас. Обычно достаточно SSH-туннеля и адреса http://127.0.0.1:8493.
Экран входа в веб-интерфейс
🔑 Два способа входа

1. Администратор — логин и пароль, заданные при первичной настройке; видит и настраивает всё.

2. Пользователь-ящик — вход по email и паролю самого почтового ящика (пароль проверяется прямым подключением к IMAP). Такой пользователь видит только свой ящик: может просматривать письма, запускать копирование, экспорт и восстановление своего ящика (раздел «Почта» → «Выгрузить» / «Восстановить в ящик»), но не может менять срок хранения и расписания, загружать .pst и не видит чужие ящики, общий журнал и логины администраторов. Ящик должен быть заранее добавлен администратором и включён.

Число проверок пароля ящика на почтовом сервере ограничено (10 на ящик и 60 на все ящики за 15 минут), чтобы страницу входа нельзя было использовать для подбора паролей почты и чтобы защита почтового сервера (fail2ban) не заблокировала адрес архива. Если этот вход не нужен — выключите «Настройки → Безопасность → Вход сотрудников по паролю ящика».

5. Дашборд и мониторинг

Главный экран показывает всё важное сразу: число ящиков, писем в архиве, что сейчас в очереди/работе, свободное место, живую ленту текущих операций с прогрессом, график активности и список ящиков с кнопкой быстрого копирования.

Дашборд: статистика и текущие операции обновляются в реальном времени

Блок «Текущие операции» обновляется автоматически (через WebSocket). Для каждой операции виден процент выполнения, скорость, объём и кнопка отмены.

6. Просмотр писем

Раздел «Почта» — это встроенный почтовый клиент для чтения писем из локальной копии, без подключения к серверу. Слева — папки, посередине — список писем, справа — само письмо.

Просмотр писем: папки → список → чтение письма

Возможности просмотра:

  • чтение текста письма и HTML-версии (HTML открывается в изолированной «песочнице» — скрипты не выполняются, это безопасно);
  • заголовки: от кого, кому, копия, дата;
  • вложения — со скачиванием по клику; картинки, вложенные в само письмо (логотип в подписи, скриншот в тексте), показываются прямо в тексте — они берутся из архива, а не из интернета;
  • скачивание письма целиком в формате .eml;
  • непрочитанные письма выделены жирным, помеченные — звёздочкой; постранично.
Где взять письма для просмотра Список формируется из локальной копии, поэтому сначала выполните резервное копирование ящика. Открыть просмотр можно из раздела «Почта» (администратор выбирает ящик сверху) или из меню ящика (⋯ → «Просмотр писем»). Пользователь, вошедший по учётным данным ящика, сразу попадает в просмотр своей почты.
Логотип из подписи показывается сразу: картинка берётся из самого письма, внешнее не загружается

Поиск по письмам

Над списком писем — строка поиска: по теме, отправителю и получателям, именам вложений и тексту писем. Администратор может искать во всех ящиках сразу, сотрудник — только в своём.

Письма заранее разбираются в индекс (SQLite FTS5) — поэтому поиск мгновенный. Новые письма индексируются в фоне каждые 10 минут; первое индексирование большого архива идёт часы, но искать можно сразу — по уже проиндексированной части. При включённом шифровании копии текст писем по умолчанию не индексируется (индекс в базе открыт): ищутся тема, адреса и имена вложений. Каждый поиск администратора записывается в аудит — это доступ к чужой переписке.

7. Аналитика

Два раздела аналитики доступны только администратору. Пользователь, вошедший по адресу и паролю почтового ящика, их не видит. Все графики рисуются прямо в браузере, без обращения к внешним сервисам — интерфейс полностью работает в закрытом контуре.

Раздел «Аналитика» — состояние системы

Отвечает на вопрос «как работает сервис»: сколько хранится, что происходит с заданиями, не заканчивается ли место. Сверху выбираются область (все ящики или один) и период графика активности (30 дней, 90 дней, полгода, год).

«Аналитика»: плитки состояния и активность по дням

Плитки показывают: письма в архиве, объём копий и средний размер письма, число ящиков и папок, задания и долю успешных, прогоны копирования, экспорты, расписания, свободное место, размер базы, пользователей и сессии, состояние планировщика.

  • Активность по дням — график с переключателем метрики: письма, объём, задания, ошибки;
  • Задания по статусам и типам — кольцевая диаграмма и столбцы;
  • Длительность заданий — среднее и максимальное время по типам (рост средней длительности бэкапа — повод проверить сеть или почтовый сервер);
  • Экспорт по форматам и движкам, хранилище по ящикам, ближайшие запуски расписаний и топ действий из журнала аудита.
На что смотреть в первую очередь Доля успешных заданий заметно ниже 100 %, ненулевые ошибки на графике активности и мало свободного места — три признака того, что с резервным копированием нужно разбираться сейчас.

Раздел «Аналитика писем» — содержание почты

Отвечает на вопрос «что лежит в ящике»: кто пишет, когда, насколько объёмные письма, о чём они. Сверху выбирается ящик или «Все ящики». Раздел состоит из двух частей.

«Аналитика писем»: показатели по индексу писем и динамика

Быстрая часть считается по индексу писем (тема, отправитель, дата, размер, флаги, папка) и работает мгновенно даже на больших ящиках:

  • всего писем и период, объём, средний и медианный размер, число отправителей и доменов;
  • доля писем с вложениями и доля непрочитанных, ответы и пересылки, важные письма;
  • динамика по месяцам, распределение по годам, дням недели и часам суток;
  • тепловая карта «день недели × час» — наглядно показывает рабочие часы и активность в выходные;
  • гистограмма размеров — что именно занимает место;
  • топ отправителей и доменов, разбивка по папкам, облако частых слов из тем;
  • крупнейшие письма — таблица самых тяжёлых писем.

Глубокий анализ содержимого вскрывает каждое письмо (файл .eml) и извлекает то, чего нет в индексе. Это тяжёлая операция, поэтому она вынесена в фоновое задание: нажмите «Запустить анализ» (или «Пересчитать»), а прогресс смотрите в разделе «Очередь и задания». Результат сохраняется и при следующем открытии показывается сразу, с датой расчёта.

  • число вложений, их объём и в скольких письмах встречаются;
  • типы вложений — по расширению (pdf, docx, xlsx, zip…) и по MIME-типу;
  • домены получателей — кому писали (поля «Кому» и «Копия»);
  • формат тела (текст / HTML / оба) и язык (русский, латиница, смешанный);
  • средняя длина текста и облако частых слов по содержимому писем.
Сколько это занимает Анализ читает каждое письмо с диска: ориентировочно 3–4 секунды на 650 писем, на ящике в 100 тысяч писем — несколько минут. Задание можно отменить в любой момент; на резервное копирование оно не влияет. Аналитика только читает данные — ни на сервере, ни в локальных копиях ничего не изменяется.

Одинаковые вложения — сколько места сэкономит хранение одной копии

Прайс, разосланный всем сотрудникам, — это сотни одинаковых PDF; логотип в подписи — картинка в каждом письме; договор, пересланный по цепочке, — ещё десяток копий. Блок «🧬 Одинаковые вложения» внизу раздела «Аналитика» считает, сколько места освободилось бы, если хранить каждое одинаковое вложение один раз. Формат хранения при этом не меняется — это только подсчёт, чтобы решить, стоит ли менять хранение.

Главная цифра — «Освободится»; ниже — самые повторяющиеся файлы, разбивка по типам и ящикам
  • Вложения сравниваются по содержимому (отпечаток SHA-256): одинаковыми считаются файлы с одним содержимым, даже если имена разные. Вложения меньше 1 КБ не учитываются.
  • «Посчитать» ставит фоновое задание. Первый подсчёт читает весь архив (часы на большом архиве), идёт частями и пропускает вперёд копирования ящиков; отчёт по прочитанной части виден сразу. Следующие подсчёты читают только новые письма.
  • «Только внутри ящиков» — экономия, если объединять копии лишь в пределах одного ящика: обычно она намного меньше, основной выигрыш — на рассылках всем сотрудникам. Отдельно показано, сколько дало бы хранение вложений без кодировки base64 (она увеличивает файлы на треть), и письма-двойники целиком.
  • Кнопка ✉️ в таблице открывает одно из писем с этим вложением.

8. Добавление почтового ящика

Раздел «Почтовые ящики» → кнопка «Добавить ящик». Заполните форму. У каждого поля есть подсказка «?» — наведите на неё, чтобы прочитать описание, рекомендацию и пример.

Форма ящика. Наведение на «?» показывает подсказку к полю
  1. Введите название (любое понятное имя), адрес IMAP-сервера и порт.
  2. Выберите шифрование (обычно SSL/TLS, порт 993).
  3. Укажите логин и пароль. Для большинства провайдеров нужен «пароль приложения» (см. ниже).
  4. Нажмите «Проверить подключение» — сервис попробует войти и покажет список папок.

Gmail и Microsoft 365, как правило, требуют вход через OAuth2 — выберите этот способ и заполните соответствующие поля.

9. Сотрудники

Раздел «Сотрудники» (виден только администратору) — справочник людей организации и связь каждого из них с почтовым ящиком. В разделе «Почтовые ящики» видны технические записи: адрес, сервер, логин; по ним не всегда понятно, чья это почта. Справочник добавляет ФИО, должность и отдел и позволяет завести ящики сразу на весь список из кадровой выгрузки, а не по одному вручную.

Что можно делать: добавить сотрудника, изменить карточку (✏️), удалить (✕), загрузить список из файла («⬆️ Импорт из файла»), синхронизировать с источником из настроек («↻ Синхронизировать»), посмотреть шаблон создаваемых ящиков («🧩 Шаблон ящиков») и скачать готовый образец файла («📄 Образец файла»). Сверху — счётчики: сколько сотрудников, у скольких есть ящик и у скольких его нет. Под заголовком — плашка источника: откуда берётся список, включено ли расписание и кнопка «🔍 Проверить источник», которая читает источник и показывает число строк, ничего не меняя в справочнике. Ниже — поиск по ФИО, почте и отделу.

Удаление сотрудника не трогает почту Удаляется только карточка из справочника. Почтовый ящик остаётся в разделе «Почтовые ящики», а локальные копии писем — на диске.

Файл со списком

Подходят CSV и Excel (.xlsx). Первая строка — заголовки, порядок столбцов любой, лишние столбцы игнорируются. Названия распознаются без учёта регистра: ФИО (или «Имя», «Сотрудник»), E-mail («Почта», «Адрес»), Должность, Отдел, Телефон, Табельный номер («ID», «Код»). Кодировка определяется автоматически — UTF-8 и Windows-1251.

После загрузки показывается отчёт: сколько карточек добавлено и обновлено, сколько ящиков создано и привязано, и список строк, которые не удалось разобрать — с номером строки и причиной.

Форматы выгрузки

Читаются CSV, Excel (.xlsx) и «Таблица XML 2003» (SpreadsheetML) — в таком виде выгружают списки интранет-справочники и корпоративные системы. Формат определяется по содержимому, поэтому неважно, как называется файл и что отдаёт сервер по ссылке (.xls, .xml или вовсе без расширения).

В XML-выгрузках разбираются их особенности: ФИО тремя колонками («фамилия», «имя», «отчество») склеивается в одно; колонка без заголовка со значениями «да»/«нет» читается как признак «работает» (строки с «нет» в справочник не попадают и ящик им не заводится); пустой заголовок сразу после «имени» — это отчество; из нескольких телефонов в карточку идёт мобильный, затем рабочий, затем внутренний; HTML внутри ячейки убирается. Такие файлы часто невалидны как XML — разбор к этому устойчив.

Если один адрес встречается у нескольких сотрудников (общий ящик склада или сервиса), карточка заводится одна, а в итоге синхронизации сообщается, какие адреса повторяются.

Пароли ящиков из файла

Ящики, заведённые сотрудникам автоматически, создаются без пароля. Чтобы не открывать сотни карточек по одной: «Почтовые ящики» → «🔑 Загрузить пароли». Файл — XLSX, CSV или XML-таблица из двух колонок: адрес ящика и пароль; заголовки необязательны. Ящик ищется по логину, а если такого логина нет — по адресу сотрудника из справочника. Галочка «Включить ящики после установки пароля» сразу включает выключенные. В отчёте видно, сколько ящиков обновлено и включено, для каких адресов ящик не нашёлся и какие строки не разобраны.

⚠ Что происходит с паролями Пароли сохраняются в базе зашифрованными, в журнал и обратно в интерфейс не попадают, а загруженный файл удаляется с сервера сразу после разбора — и при успехе, и при ошибке. В аудит пишутся только счётчики и имя файла.

Откуда берётся список: файл или URL

Источник выбирается настройкой «Источник списка» в «Настройки» → «Сотрудники».

  • Файл на сервере — служба читает CSV/XLSX по пути на диске, например /var/lib/mailarchiver/hr/employees.csv. Подходит, когда кадровая система кладёт файл на сервер или в смонтированную сетевую папку. Файл читает служба mailarchiver — у неё должны быть права на чтение.
  • Адрес (URL) — служба сама скачивает выгрузку по ссылке http(s):// перед каждой синхронизацией; копировать файл на сервер архива не нужно. Можно задать логин и пароль (HTTP Basic), таймаут, проверку сертификата и формат ответа. Пароль хранится в базе зашифрованным и в интерфейс не возвращается.

Загрузка по ссылке проверяет ответ сама: HTML-страница входа вместо файла, ответы 401/403, размер больше 20 МБ и неверно угаданный формат объясняются понятным текстом, а не ошибкой разбора. XLSX опознаётся по содержимому, даже если в ссылке нет расширения.

💡 Проверяйте источник кнопкой «🔍 Проверить источник» читает файл или скачивает ссылку и показывает, сколько строк нашлось и какие из них проблемные. Справочник при этом не меняется — можно спокойно проверять адрес до включения расписания.

Автоматическая синхронизация

Настраивается в «Настройки» → раздел «Сотрудники»: включение, источник (файл или URL), расписание (по умолчанию 0 5 * * * — ежедневно в 05:00) и признак «заводить ящики новым сотрудникам». Синхронизация выполняется обычным фоновым заданием, поэтому её ход виден в разделе «Очередь и задания».

Правила сопоставления: сначала по табельному номеру, при его отсутствии — по адресу почты. Новые карточки добавляются, у существующих обновляются только заполненные поля — пустые значения в файле ничего не затирают.

Уволенные не обрабатываются автоматически Сотрудники, исчезнувшие из файла, остаются нетронутыми: ничего не выключается и не удаляется. Это защита от того, чтобы сбой выгрузки или случайно урезанный файл не остановили копирование почты у половины организации. Уволенных администратор обрабатывает вручную.

Уволенные сотрудники

Ящик уволенного на почтовом сервере обычно удаляют, а переписка может понадобиться через годы. Когда сотрудник становится уволенным — вручную (статус «Уволен (архив удерживается)» в карточке), по выгрузке («Работает: нет», «Уволен: да», прошедшая «Дата увольнения») или по отсутствию в выгрузке N дней, — MailArchiver:

  1. сразу ставит последнюю копию ящика в очередь (пока ящик ещё есть на сервере);
  2. после неё выключает копирование ящика;
  3. удерживает архив N лет (по умолчанию 5): письма не удаляются по сроку хранения, даже если у ящика срок «3 дня».
Уволенный сотрудник: копирование выключено, архив удерживается до указанной даты

Если одна синхронизация отмечает уволенными больше 20 % работающих, это похоже на испорченную выгрузку: увольнения не применяются, а в итоге синхронизации появляется предупреждение. Вернувшийся сотрудник («Работает») получает ящик обратно — копирование включается, удержание из-за увольнения снимается. В разделе «Почтовые ящики» есть отборы «Уволенные сотрудники», «Архив удерживается» и «Удержание истекло» (сам архив по истечении удержания не удаляется — решение за администратором).

10. Резервное копирование

Запустить копирование вручную можно из раздела «Почтовые ящики»:

  • «💾 Копия сейчас» в строке ящика (или пункт «Сделать резервную копию сейчас» в меню «⋯») — копирование одного выбранного ящика;
  • «💾 Копия всех ящиков сейчас» — кнопка вверху справа ставит в очередь копирование всех включённых ящиков разом. Программа спросит подтверждение и покажет, сколько ящиков будет обработано. Выключенные ящики пропускаются, а ящики, по которым копирование уже идёт, не запускаются повторно — поэтому случайное повторное нажатие не удваивает нагрузку.

Кроме того, копирование запускается автоматически по расписанию (раздел «Расписания»).

Поиск и отбор ящиков

Над списком — строка поиска (по названию, логину и серверу) и отбор по состоянию: все, только включённые, только выключенные, без пароля и готовые к копированию (включён и пароль задан). Рядом с каждым пунктом показано число ящиков, а справа — «показано N из M». Это нужно, когда ящиков сотни: после синхронизации сотрудников они заводятся выключенными и без пароля, и найти их глазами в общем списке невозможно.

Копирование инкрементальное — при повторных запусках докачиваются только новые письма, поэтому оно быстрое. Прогресс виден в разделе «Очередь и задания».

Скопировать заново

Меню ящика «⋯» → «🔄 Скопировать заново». Два режима:

  • Докачать потерянные письма (безопасный, выбран по умолчанию) — сервис сверяет индекс с файлами на диске и, если файл письма пропал или оказался пустым (сбой диска, оборванный прогон, чужая уборка), убирает запись из индекса, чтобы письмо скачалось заново. Ничего не удаляется.
  • Полностью с нуля — стирает локальную копию ящика (и файлы писем, и записи индекса) и скачивает всё с сервера заново. Доступно только администратору, запрашивает подтверждение и записывается в аудит.
⚠️ Режим «с нуля» необратим Письма, которых уже нет на почтовом сервере, существуют только в этой копии — после стирания их не вернуть. Выбирайте этот режим, только если архив испорчен и нужен именно чистый лист; в остальных случаях хватает «докачать потерянные».
💡 Рекомендация Настройте расписание на ночное время (например, 0 3 * * *). Так копирование не будет мешать работе и меньше нагрузит почтовый сервер.

Почему .pst — особый случай Формат PST — закрытый формат Microsoft. На Linux надёжно создавать корректный .pst умеет по сути только коммерческая библиотека Aspose.Email; полностью бесплатных генераторов .pst под Linux не существует (open-source умеет только читать .pst). Поэтому MailArchiver предлагает: надёжный путь через Aspose, встроенный бесплатный экспериментальный генератор (папки, тема, адреса, дата и текст — без вложений) и всегда доступные EML/MBOX, которые Outlook импортирует без потерь.

Версии Outlook: ANSI или Unicode

Параметр «Формат PST» определяет совместимость:

  • ANSI — для очень старого Outlook 97–2002. Ограничение размера 2 ГБ.

Просто выберите вашу версию Outlook в поле «Целевая версия Outlook» — формат подберётся автоматически.

12. Восстановление на сервер

Если письма пропали на почтовом сервере, их можно вернуть из локальной копии. Откройте ящик (меню «⋯») → «Восстановить на сервер».

💡 Безопасный порядок 1) Сначала сделайте пробный прогон (галочка «Пробный прогон») — он посчитает письма, но ничего не зальёт. 2) Заливайте в режиме «В папки с префиксом» (например, «Восстановлено») — так восстановленные письма не смешаются с текущей почтой. 3) Оставьте включённой галочку «Пропускать дубли» — можно безопасно перезапускать.

Восстановление сохраняет флаги (прочитано/важное) и дату получения писем.

Импорт из существующего .pst

Меню ящика → «Импорт из .pst»: загрузите PST-файл, и его письма зальются на IMAP-сервер в папку с указанным префиксом. Для этого на сервере должен быть установлен readpst (пакет pst-utils) — скрипт установки ставит его автоматически, в Docker он уже включён.

Хранение копий: 3 дня / 1 неделя

Можно ограничить, за какой период хранить локальные копии писем каждого ящика — например, только за последние 3 дня или 1 неделю от текущей даты. Копии старше выбранного срока удаляются автоматически (ежедневная очистка). На письма на самом почтовом сервере это не влияет.

Пресеты хранения: последние 3 дня, последняя неделя, хранить всё или свой срок

Открыть: меню ящика (⋯) → «Хранение копий» (в том числе свой срок в днях), либо задать в форме ящика поле «Хранение локальных копий». Очистку раз в сутки запускает планировщик для всех ящиков, у которых есть что удалять (время — «Настройки → Хранение и очистка → Время ежедневной очистки», по умолчанию 04:30). Значение «по глобальной настройке» берёт срок «Хранить дней» из раздела «Хранение и очистка» — он действует, только когда там включена «Общая очистка по сроку».

Удалённые по сроку письма не скачиваются следующим копированием заново. Если срок увеличить (или выбрать «хранить всё»), письма, которые ещё лежат на сервере, снова попадут в копию.

⚠ Обратите внимание Ретеншн удаляет именно локальные копии старше срока. Если нужен полный «вечный» архив — оставьте «Хранить всё». Хранение за 3 дня/неделю удобно, когда важны только свежие письма и экономия места.

14. Настройки — справочник всех параметров

Раздел «Настройки» сгруппирован по темам. У каждого параметра есть подсказка «?» с описанием, рекомендацией и примером. Ниже — полный справочник тех же параметров.

Подсказка к параметру: описание, рекомендация (💡), пример и значение по умолчанию

🌐 Сервер и сеть

Адрес прослушиванияserver.host

IP-адрес, на котором веб-интерфейс принимает подключения. 127.0.0.1 — только с самого сервера (безопасно, обычно за reverse proxy). 0.0.0.0 — со всех сетевых интерфейсов.

💡 Оставьте 127.0.0.1 и поставьте перед сервисом nginx/traefik с HTTPS. Ставьте 0.0.0.0 только если понимаете риски и включили аутентификацию.

Пример: 127.0.0.1 · По умолчанию: 127.0.0.1

Порт веб-интерфейсаserver.port

TCP-порт, на котором работает веб-интерфейс.

💡 Порт по умолчанию 8493 подходит в большинстве случаев. Меняйте, если он занят.

Пример: 8493 · По умолчанию: 8493

Внешний URLserver.public_url

Полный адрес, по которому интерфейс открывают в браузере. По нему проверяется источник запросов (защита от подделки запросов с чужих сайтов), в том числе у WebSocket — за обратным прокси, который меняет заголовок Host, без него интерфейс работать не будет.

💡 Заполните, если работаете за reverse proxy с доменом и HTTPS.

Пример: https://mail-backup.example.ru · По умолчанию: (пусто)

За обратным проксиserver.behind_proxy

Доверять заголовкам X-Forwarded-* (реальный адрес клиента, протокол). Включайте, только если перед сервисом стоит доверенный nginx/traefik, и обязательно заполните «Адреса доверенных прокси».

💡 true при работе за reverse proxy, иначе false.

Пример: false · По умолчанию: false

Адреса доверенных проксиserver.trusted_proxies

Кому можно верить в заголовке X-Forwarded-For. Настоящим адресом клиента считается первый справа хоп, которого нет в этом списке: левую часть цепочки дописывает сам клиент, и без списка защиту от подбора пароля обходит любой, кто подставит заголовок. Допустимы отдельные адреса и сети (10.0.0.0/8), через запятую.

💡 Адрес вашего nginx/traefik. «*» отключает проверку — так делать не нужно.

Пример: 127.0.0.1, 10.0.0.0/8 · По умолчанию: 127.0.0.1, ::1

Требовать входsecurity.auth_enabled

Через сколько часов после входа сессия истечёт и потребуется войти заново.

💡 8–12 часов для рабочего дня. Меньше — безопаснее, но чаще вход.

Автоматический выход при отсутствии активности указанное число минут.

💡 30–60 минут. Для строгих требований — 15.

Пример: 60 · По умолчанию: 60

Минимальная длина пароляsecurity.min_password_length

Минимальное число символов в пароле пользователя веб-интерфейса.

💡 Не меньше 8; лучше 12+ и парольная фраза.

Пример: 8 · По умолчанию: 8

Порог блокировки входаsecurity.max_login_attempts

Сколько неудачных попыток входа допускается для одной учётной записи с одного адреса; затем этот адрес для неё временно блокируется (чужие попытки не закрывают вход настоящему владельцу). От этого числа считаются и остальные пределы: адрес по всем учётным записям — ×10; неверные коды 2FA по учётной записи — ×2 за период блокировки и ×10 за сутки (резервные коды при этом работают); проверки пароля одного почтового ящика — ×2, всех ящиков вместе — ×12.

💡 5 — разумный баланс. Слишком мало мешает при опечатках.

Пример: 5 · По умолчанию: 5

Длительность блокировки, минутsecurity.lockout_minutes

На сколько минут блокируется вход после превышения порога попыток (и за какой период они считаются).

💡 15 минут.

Пример: 15 · По умолчанию: 15

Cookie только по HTTPSsecurity.secure_cookie

Помечает cookie сессии флагом Secure — браузер отправит её только по HTTPS.

💡 Включите, когда сервис доступен по HTTPS. По HTTP держите выключенным, иначе вход не сработает.

Пример: false · По умолчанию: false

Обязательный двухфакторный входsecurity.require_2fa

Каждый администратор обязан включить вход с кодом из приложения-аутентификатора (Яндекс Ключ, Google Authenticator и т. п.). Пока 2FA не включена, после входа открывается только её настройка. Вход сотрудников по своему ящику это не затрагивает.

💡 true, если интерфейс доступен из интернета или из общей сети офиса.

Пример: true · По умолчанию: false

Вход сотрудников по паролю ящикаsecurity.mailbox_login

Сотрудник входит в веб-интерфейс своим email и паролем почтового ящика и видит только свой архив. Пароль проверяется входом на почтовый сервер. Число таких проверок ограничено (на ящик и в целом), чтобы страницу входа нельзя было использовать для подбора паролей почты, а защита почтового сервера не заблокировала адрес MailArchiver.

💡 Выключите, если сотрудникам не нужен доступ к своему архиву или почтовый сервер строго блокирует адреса после неудачных входов (fail2ban).

Пример: true · По умолчанию: true

Проверять TLS-сертификат IMAPsecurity.imap_ssl_verify

Проверять подлинность сертификата почтового сервера при подключении по SSL/STARTTLS.

💡 Держите включённым. Отключайте только для внутренних серверов с самоподписанным сертификатом — это снижает защиту от подмены.

Пример: true · По умолчанию: true

💾 Хранилище

Сжимать письма (gzip)storage.compress

Сжимать каждое письмо при сохранении. Экономит место (текстовые письма сжимаются в 2–4 раза), но чуть увеличивает нагрузку на процессор.

💡 Включайте при нехватке места. Для максимальной скорости и совместимости с внешними инструментами — выключено.

Пример: false · По умолчанию: false

Принудительный сброс на дискstorage.fsync

После записи письма принудительно сбрасывать данные на диск (fsync). Надёжнее при сбоях питания, но медленнее.

💡 Включено для надёжности. Выключайте только на быстрых SSD, где важна максимальная скорость.

Пример: true · По умолчанию: true

Минимум свободного места, МБstorage.min_free_space_mb

Если свободного места меньше этого значения, бэкап не начнётся (защита от заполнения диска).

💡 500–2000 МБ. Для больших ящиков увеличьте.

Пример: 500 · По умолчанию: 500

Проверять после записиstorage.verify_after_write

После сохранения письма сверять его размер и контрольную сумму (SHA-256). Гарантирует, что копия записалась без повреждений.

💡 Держите включённым — стоит недорого, а защищает от «тихой» порчи данных.

Пример: true · По умолчанию: true

Шифровать письмаstorage.encrypt

Новые письма сохраняются зашифрованными (AES-256-GCM). Уже сохранённые остаются как были — зашифровать их можно кнопкой ниже. Без файла ключа зашифрованные письма НЕ ПРОЧИТАТЬ ничем: храните копию ключа отдельно от каталога данных. Выгрузки (EML/MBOX/PST) не шифруются.

💡 Включайте, если копии каталога писем уходят на внешние диски или в облако, а ключ хранится отдельно. От кражи всего сервера целиком не защищает — для этого шифрование диска (LUKS).

Пример: true · По умолчанию: false

Файл ключа шифрованияstorage.encryption_key_file

Путь к файлу ключа (64 шестнадцатеричных символа). Пусто — storage.key в каталоге данных (создаётся автоматически при первом включении). Надёжнее вынести ключ из каталога данных: создайте его командой «mailarchiver storage-key --generate ПУТЬ».

💡 Путь вне каталога данных, например /etc/mailarchiver/storage.key (права 0640, группа службы).

Пример: /etc/mailarchiver/storage.key · По умолчанию: (пусто)

💡 120. Для очень больших писем/вложений увеличьте до 300.

Сохранять пометки писем (прочитано, важное, отвечено и т.п.). Нужно, чтобы при восстановлении статусы вернулись как были.

💡 Включено.

Пример: true · По умолчанию: true

Пропускать письма крупнее, МБbackup.skip_larger_than_mb

Не сохранять письма больше указанного размера (0 — сохранять все). Полезно, если не нужны гигантские вложения.

💡 0 (сохранять всё). Ставьте, например, 50, если хотите исключить огромные вложения.

Пример: 0 · По умолчанию: 0

Терпеть нечитаемую папку, прогоновbackup.unreadable_folder_grace_runs

Сколько прогонов подряд папка, которую почтовый сервер отказывается открыть, считается ОШИБКОЙ и делает копию неполной. После этого числа она переходит в разряд «известных нечитаемых»: сервис продолжает пробовать её каждый раз, сообщает о ней в итоге задания, но задание больше не помечается неудачным. Как только сервер отдаст папку, счётчик сбрасывается и письма копируются. 0 — считать ошибкой всегда.

💡 3. Бесконечное «КОПИЯ НЕПОЛНАЯ» из-за папки, которую на сервере уже не починить, приучает не читать предупреждения — и настоящая пропажа писем остаётся незамеченной.

Пример: 3 · По умолчанию: 3

Регулярно сверять справочник сотрудников с файлом-выгрузкой из кадровой системы: новые сотрудники добавляются, у существующих обновляются должность, отдел и телефон. Уволенные (те, кто пропал из файла) НЕ отключаются и не удаляются — это делает администратор вручную.

💡 Включайте, когда путь к файлу задан и пробная синхронизация кнопкой «Синхронизировать» прошла без ошибок.

Пример: false · По умолчанию: false

Источник спискаemployees.source_type

Откуда брать список сотрудников: «Файл на сервере» — служба читает CSV/XLSX по пути на диске; «Адрес (URL)» — служба сама скачивает выгрузку по ссылке http(s) при каждой синхронизации.

💡 URL удобнее, когда кадровая система умеет отдавать выгрузку ссылкой: файл не нужно копировать на сервер архива.

Пример: file · По умолчанию: file

Файл-источникemployees.source_file

Путь на сервере к файлу со списком сотрудников (CSV или XLSX); используется, когда источник — «Файл на сервере». Первая строка — заголовки: ФИО, E-mail, Должность, Отдел, Телефон, Табельный номер. Кодировка и разделитель определяются автоматически.

💡 Положите выгрузку в отдельный каталог, куда кадровая система кладёт файл по расписанию. Формат файла можно посмотреть, скачав образец в разделе «Сотрудники».

Пример: /var/lib/mailarchiver/hr/employees.csv · По умолчанию: (пусто)

Адрес выгрузки (URL)employees.source_url

Ссылка http:// или https://, по которой отдаётся файл со списком сотрудников (CSV или XLSX). Используется, когда источник — «Адрес (URL)». Содержимое и заголовки ответа проверяются: если по ссылке придёт страница входа, синхронизация об этом прямо скажет.

💡 Спросите у администратора кадровой системы прямую ссылку на выгрузку. Внутри организации обычно достаточно https-адреса без дополнительных ключей.

Пример: https://hr.example.ru/export/employees.csv · По умолчанию: (пусто)

Логин источникаemployees.source_url_user

Имя пользователя для HTTP Basic, если выгрузка закрыта паролем. Оставьте пустым для открытой ссылки.

💡 Заводите для архива отдельную учётную запись «только чтение» — так её можно отозвать, не трогая остальных.

Пример: mailarchiver · По умолчанию: (пусто)

Пароль источникаemployees.source_url_password

Пароль HTTP Basic к адресу выгрузки. Хранится в базе в зашифрованном виде и не показывается в интерфейсе. Пустое поле при сохранении означает «оставить прежний пароль».

💡 Заполняйте только если сервер-источник действительно требует авторизацию.

Пример: (скрыт) · По умолчанию: (пусто)

Проверять сертификат источникаemployees.source_url_verify_ssl

Проверять TLS-сертификат сервера, с которого скачивается выгрузка. Выключение делает соединение уязвимым к подмене — оставляйте включённым, пока это возможно.

💡 Выключайте только для внутреннего сервера с самоподписанным сертификатом, когда выпустить доверенный нельзя.

Пример: true · По умолчанию: true

Таймаут загрузки, сemployees.source_url_timeout_s

За сколько секунд выгрузка должна скачаться ЦЕЛИКОМ (соединение, ответ сервера и все данные). Обрыв или неполный ответ отвергаются — частичный список не применяется.

💡 60 с хватает почти всегда. Увеличьте до 180–300, если кадровая система формирует выгрузку прямо в момент запроса.

Пример: 60 · По умолчанию: 60

Формат ответаemployees.source_url_format

Чем разбирать скачанное: «Определять автоматически» (по заголовку Content-Disposition, расширению в ссылке и содержимому), «CSV» или «Excel (XLSX)».

💡 Оставьте автоматически. Задавайте формат явно, если ссылка вида /export?id=5 не содержит имени файла и определение ошибается.

Пример: auto · По умолчанию: auto

Cron-выражение из пяти полей: минуты часы день месяц день_недели. «0 5 * * *» — каждый день в 05:00, «0 5 * * 1» — по понедельникам в 05:00.

Заводить ящики новым сотрудникамemployees.create_accounts

Создавать почтовый ящик для НОВОГО сотрудника, у которого в файле указан e-mail. Ящик создаётся ВЫКЛЮЧЕННЫМ и без пароля: копирование не начнётся, пока администратор не впишет пароль и не включит ящик. Если ящик с таким логином уже есть, он просто привязывается. Нужен «IMAP-сервер новых ящиков»: без него ящики не заводятся. Ящик, который администратор удалил или отвязал, заново не создаётся.

💡 Оставьте включённым: карточка сотрудника сразу связана с ящиком, останется только задать пароль.

Пример: true · По умолчанию: true

🗝️ Вход в ящики через администратора почты

Входить в ящики через администратораmailadmin.enabled

Копировать ящики, не зная паролей сотрудников: служба входит учётной записью администратора почты «от имени» ящика. Так не нужно собирать и обновлять сотни паролей. Работает, только если почтовый сервер это умеет: Dovecot (master users), Cyrus, Zimbra (SASL PLAIN с authzid). Axigen такой вход в документации не описывает — проверьте кнопкой «Проверить вход администратора»; если сервер откажет, оставьте вход по паролям. Ящикам с входом через администратора пароль не нужен (в карточке ящика — «Способ входа: через администратора почты»).

💡 Включайте, если сервер поддерживает такой вход, и используйте отдельную учётную запись только для архива.

Пример: true · По умолчанию: false

16. Безопасность

  • Вход по паролю. Пароли пользователей хранятся в виде необратимого хеша (PBKDF2-HMAC-SHA256). Защита от подбора блокирует конкретный источник, а не учётную запись: 5 неудач с одного адреса — блокировка этого адреса для учётной записи, 50 по всем учётным записям — блокировка адреса; попытки со всех адресов на одну учётную запись только замедляют ответ, чтобы злоумышленник не мог «выключить» вход владельцу.
  • Шифрование секретов ящиков. Пароли и токены IMAP-ящиков хранятся в БД в зашифрованном виде (Fernet/AES). Ключ лежит в файле secret.key с правами только для владельца.
  • Сессии. Cookie сессии подписаны и ограничены по времени; есть авто-выход при бездействии — открытая, но забытая вкладка сеанс не продлевает. Когда сеанс закончился, интерфейс показывает форму входа и возвращает в тот же раздел.
  • Письма в браузере. HTML письма показывается в песочнице без скриптов и с собственной политикой безопасности: внешние картинки, стили и шрифты (трекинг-пиксели) не загружаются, пока вы не нажмёте «Показать картинки».

Двухфакторный вход (2FA)

Включение: QR-код для приложения и ключ для ручного ввода

После пароля запрашивается шестизначный код из приложения на телефоне (Яндекс Ключ, Google Authenticator, Microsoft Authenticator, FreeOTP). Включение: своё имя внизу меню → отсканируйте QR-код → введите код → сохраните 10 резервных кодов (каждый действует один раз, если телефона нет под рукой). Сделать 2FA обязательной для всех администраторов: «Настройки → Безопасность → Обязательный двухфакторный вход».

  • На один вход — 5 минут и 3 попытки ввода кода; смена пароля отзывает выданные «билеты» второго шага.
  • 10 неверных кодов за 15 минут (или 50 за сутки) со всех адресов блокируют ввод кодов из приложения и отправляют уведомление: пароль, видимо, известен постороннему — смените его. Резервные коды при этом работают.
  • Потерян телефон: войдите резервным кодом; нет кодов — другой администратор сбросит 2FA в разделе «Пользователи», единственный администратор — командой sudo mailarchiver reset-2fa -u admin.

Шифрование локальной копии писем

По желанию письма на диске хранятся зашифрованными (AES-256-GCM, свой ключ на каждый файл). Просмотр, экспорт и восстановление работают как обычно — расшифровка идёт «на лету». Включение: «Настройки → Хранилище → Шифровать письма» (ключ будет создан в каталоге данных) или заранее созданный ключ вне каталога данных:

sudo mailarchiver storage-key --generate /etc/mailarchiver/storage.key
sudo chown root:mailarchiver /etc/mailarchiver/storage.key && sudo chmod 640 /etc/mailarchiver/storage.key

и в настройках: «Файл ключа» = этот путь, «Шифровать письма» = да. Уже сохранённые письма шифруются кнопкой «Зашифровать уже сохранённые» в том же разделе.

⚠ Храните копию ключа отдельно от сервера Без ключа зашифрованные письма не прочитать никак. Если ключ пропал, служба перестаёт сохранять новые письма (чтобы они не легли на диск открытым текстом) и показывает на дашборде красную плашку — верните файл ключа и перезапустите службу. Состояние ключа: sudo mailarchiver storage-key.

Публикация через HTTPS (reverse proxy)

Чтобы открыть доступ извне безопасно, поставьте перед сервисом nginx или traefik с TLS. Пример nginx:

server {
  listen 443 ssl;
  server_name mail-backup.example.ru;
  ssl_certificate     /etc/letsencrypt/live/.../fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/.../privkey.pem;
  location / {
    proxy_pass http://127.0.0.1:8493;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;    # для WebSocket
    proxy_set_header Connection "upgrade";
  }
}

В настройках включите «За обратным прокси», укажите адрес прокси в «Доверенные прокси», «Внешний URL» (например https://mail-backup.example.ru) и включите «Cookie только по HTTPS».

17. Копия архива вне сервера и снимки базы

Если сервер пропадёт целиком — сгорит диск, данные зашифрует вирус-вымогатель, по ошибке удалят виртуальную машину, — вместе с ним пропадёт и архив. MailArchiver каждый день отправляет копию в другое место:

КудаКак
Сетевая папка или дисклюбой каталог, подключённый к серверу (SMB/CIFS, NFS, USB-диск)
Сервер по SSHдругой Linux-сервер, копирование rsync; вход по SSH-ключу службы
S3-хранилищеYandex Object Storage, VK Cloud, Selectel, свой MinIO
«Настройки → Копия вне сервера и снимки базы»: параметры, итог последнего прогона и кнопки
  • В копию уходят файлы писем (зашифрованные — как есть) и снимки базы — без базы копия писем была бы грудой файлов. Снимки делаются каждый день (и кнопкой), проверяются на целостность, сжимаются и шифруются ключом копии писем; 3 последних хранятся и на самом сервере.
  • Каждый день отправляется только новое; удалённое из архива удаляется и в копии — но не больше 50 % за прогон без явного разрешения: так выглядит отключившийся диск, а не обычная очистка.
  • Метка .mailarchiver-replica не даёт писать копию в пустую точку монтирования отключённого диска или в чужую папку: если метка пропала там, где копия уже была, прогон останавливается с понятной ошибкой.
  • Раз в неделю список файлов в копии сверяется с архивом целиком; если копия не обновлялась больше двух суток, на дашборде появляется красная плашка.
⚠ Ключей в копии нет — и это правильно secret.key (им зашифрованы пароли ящиков) и ключ шифрования писем храните отдельно от копии: копия вместе с ключами — не защищённая копия.

Восстановление после аварии

  1. Установите MailArchiver на новый сервер и остановите службу: sudo systemctl stop mailarchiver.
  2. Скачайте копию: sudo mailarchiver replica-pull --dir /mnt/backup/mailarchiver (или --s3-endpoint … --s3-bucket … --s3-access-key … --s3-secret-key-file …). Копию по SSH верните rsync-ом.
  3. Положите secret.key в каталог данных и ключ шифрования — по пути из настроек.
  4. Восстановите базу из свежего снимка: sudo mailarchiver restore-snapshot mailarchiver-….db.gz[.enc].
  5. Проверьте ключ (sudo mailarchiver storage-key) и запустите службу.

Раз в квартал делайте пробное восстановление на тестовую машину: копия, из которой ни разу не восстанавливались, может подвести в самый нужный момент.

18. Мониторинг: Prometheus, Zabbix, еженедельная сводка

Еженедельная сводка (по понедельникам в 8:00) приходит администраторам на почту: ящики, требующие внимания (неверный пароль, давно не копировались, ошибки), итоги недели, место на диске и на сколько дней его хватит, состояние копии вне сервера, неудачные входы. В карточке «Уведомления» — «Посмотреть сводку» и «Отправить сейчас».

Метрики /metrics в формате Prometheus включаются в «Настройки → Мониторинг»: ящики по состояниям, давность последней копии каждого ящика, очередь, диск, копия вне сервера, снимки базы, неудачные входы. Доступ — только с разрешённых адресов (по умолчанию с самого сервера) или по токену Authorization: Bearer ….

Метрики включены, токен задан; внизу — пример настройки Prometheus и Zabbix
scrape_configs:
  - job_name: mailarchiver
    scheme: https
    authorization: {type: Bearer, credentials: ТОКЕН}
    static_configs: [{targets: ["mail-archive.company.ru"]}]

# тревога: ящик включён, а свежей копии нет больше трёх суток
- alert: MailboxBackupStale
  expr: (time() - mailarchiver_account_last_backup_timestamp_seconds) > 3*86400
        and mailarchiver_account_enabled == 1

Zabbix: элемент «HTTP-агент» с URL метрик и заголовком Authorization: Bearer ТОКЕН, зависимые элементы с предобработкой «Шаблон Prometheus», например mailarchiver_accounts{state="bad_password"}.

«Удаление в копии приостановлено»Прогон собирался удалить слишком много файлов — так выглядит отключившийся диск. Если удаление ожидаемо — «Разрешить удаление и запустить».
Поиск не находит письмоИндекс ещё строится («Проиндексировано N из M» над строкой поиска) или при шифровании копии текст не индексируется — ищите по теме, адресам, вложениям.
/metrics: 404, 401 или 403404 — метрики выключены; 401/403 — нет верного токена и адрес не в списке «Адреса без токена».
«Вход через учётную запись администратора почты отклонён сервером»Неверные логин/пароль администратора, не тот способ входа или сервер такой вход не умеет (Axigen).
«Выгрузка отмечает уволенными N сотрудников … НЕ применены»Больше 20 % увольнений разом — похоже на испорченную выгрузку. Проверьте файл; настоящие увольнения отметьте вручную.

Папка не открывается: failed EXAMINE

Это ответ почтового сервера: он отказался открыть папку. Прежде чем объявить копию неполной, MailArchiver делает три вещи:

  1. повторяет попытку через полторы секунды — часть отказов временная (ящик занят другой сессией);
  2. пробует открыть папку обычным SELECT вместо EXAMINE: некоторые серверы (замечено на Axigen) отказывают только на EXAMINE. Письма всё равно скачиваются командой BODY.PEEK — отметки «прочитано» на сервере не появляются;
  3. проверяет, есть ли у папки вложенные папки: если есть — это папка-контейнер, своих писем она не хранит (сервер просто не пометил её флагом \Noselect), и копия остаётся полной;
  4. спрашивает командой STATUS, сколько писем сервер видит в этой папке. 0 писем — копия остаётся полной, в журнале будет «папка ПУСТАЯ … потерь нет». N писем — задание помечается «частично выполнено» и в итоге пишется «КОПИЯ НЕПОЛНАЯ» с перечнем папок.

Что смотреть на сервере: открывается ли папка в веб-почте; имя папки (соседние имена вида s2022 и s2022_000 — признак дубликата, который сервер создал сам при конфликте имён, такие папки обычно и не открываются); права (ACL) учётной записи; не заблокирован ли ящик другой сессией. В Axigen учётную запись чинят через CLI: telnet 127.0.0.1 7000 → update domain name <домен> → REPAIR Accounts <учётка>; восстановленная копия создаётся под именем вида <учётка>.00000015.repaired и её нужно переименовать — это крайняя мера, делайте её в окно обслуживания.

Всё, что сервис пробовал и узнал, попадает в текст ошибки: «Что пробовали: EXAMINE — отказ (попыток: 2); обычный SELECT — отказ» и «Дополнительно: …». Строка «Дополнительно» отвечает на главный вопрос — кто виноват: «в списке папок сервера это имя есть … сама папка нерабочая» (чинить на почтовом сервере) либо «LIST по точному имени эту папку НЕ находит» (сервер не признаёт имя своим — беда с кодировкой или невидимым символом, его сервис назовёт: например «невидимый символ NBSP (U+00A0)»).

Папка не открывается давно — это перестаёт быть ошибкой

Папка, которую сервер не отдаёт несколько прогонов подряд, переходит в разряд «известных нечитаемых»: сервис продолжает пробовать её и продолжает писать о ней в итоге задания, но задание больше не помечается неполным. Порог задаёт настройка «Терпеть нечитаемую папку, прогонов» (Настройки → «Резервное копирование», по умолчанию 3; 0 — считать ошибкой всегда). Сломанную на сервере папку из архива не починить, а вечное «КОПИЯ НЕПОЛНАЯ» приучает не читать предупреждения — и следующая настоящая пропажа писем останется незамеченной. Как только сервер отдаст папку, счётчик сбрасывается и письма копируются как обычно.

Кнопка «Проверить папки на сервере»

«Почтовые ящики» → «⋯» у ящика → «🗂️ Проверить папки на сервере». Сервис опрашивает каждую папку и показывает таблицу с вердиктом: копируется (письма доступны), контейнер (своих писем не хранит, содержимое во вложенных папках), пустая, не открывается (терять нечего), НЕ ЧИТАЕТСЯ (вот это и есть потеря — вверху видно, сколько писем недоступно) и исключена (не копируется по настройкам ящика). Для нечитаемых там же есть кнопка «🚫 Больше не копировать эти папки».

💡 Если папку не починить Откройте «Очередь и задания» → «Детали» задания → блок «Копия неполная» → кнопка «🚫 Больше не копировать эти папки»: папки добавятся в «Пропускать папки» этого ящика (убрать можно в карточке ящика). Задание перестанет помечаться неполным из-за папок, которые на сервере всё равно не восстановить, — и следующая настоящая пропажа писем будет заметна.

20. Частые вопросы

Это удалит письма с почтового сервера?

Нет. Копирование только читает письма. Локальная копия — это надёжный архив, из которого ничего не пропадает, даже если письмо удалят на сервере. Локальные письма удаляются только по сроку хранения, который вы задали сами.

Сколько ящиков можно подключить?

Ограничений нет. Сколько заданий идёт одновременно, задаёт «Одновременных заданий» (1–16); с одним ящиком одновременно работает только одно задание.

Нужен ли интернет для экспорта в PST?

Нет, экспорт локальный. Интернет нужен только движку Aspose при первичной установке библиотеки и для OAuth2.

Где лежат копии писем?

В каталоге данных (по умолчанию /var/lib/mailarchiver/mailboxes, в Docker — том /data). Это обычные файлы .eml в структуре папок Maildir.

Можно ли перенести копии на другой сервер?

Да. Скопируйте каталог данных целиком (письма, база индексов, secret.key), config.yaml и — если включено шифрование и ключ лежит вне каталога данных — файл ключа шифрования. Без него зашифрованные письма не прочитать. Проверка на новом сервере: sudo mailarchiver storage-key.

А если сервер сгорит целиком?

Включите копию архива вне сервера (раздел 17): каждый день в сетевую папку, на другой сервер по SSH или в S3, вместе со снимками базы. Восстановление — командами replica-pull и restore-snapshot.

Можно ли не собирать пароли сотрудников?

Если почтовый сервер пускает администратора в чужие ящики (Dovecot, Cyrus, Zimbra) — да, см. «Вход в ящики через администратора почты». Axigen такой вход не документирует — проверьте кнопкой; если нет, остаются пароли ящиков.

Что будет с почтой уволенного сотрудника?

Сделается последняя копия, копирование выключится, архив будет удерживаться 5 лет (или сколько настроено) — очистка по сроку его не тронет.

Какие есть команды в консоли сервера?

mailarchiver check-config, create-admin, reset-password -u ИМЯ, reset-2fa -u ИМЯ, storage-key (и --generate ПУТЬ), replica-pull, restore-snapshot СНИМОК, replica-ssh-key, version. Установщик создаёт команду mailarchiver; запущенная через sudo, она сама работает от имени службы.

Безопасно ли открывать доступ из интернета?

Только через HTTPS (reverse proxy) и с включённой аутентификацией. Прямой доступ по HTTP наружу не рекомендуется.
